# 10 项目

项目是**有明确成果、完成条件或阶段边界，并需要多步推进的工作**。

## 建立项目的条件

同时满足以下条件时建立项目：

- 有可描述的预期成果；
- 有完成条件或明确停止条件；
- 需要多步行动、决策或材料管理；
- 需要在一段时间内持续跟踪。

单一动作不是项目；没有结束日期但要长期维持的事项属于责任领域；可复用解释属于知识。

## 状态模型

```text
planned → active → completed
          ↓   ↑
       waiting
          ↓
        paused

任意未完成状态 → cancelled
```

允许状态：

- `planned`：成果和边界已定义，尚未投入；
- `active`：正在推进；
- `waiting`：依赖他人、审批、交付或外部条件；
- `paused`：主动停止，近期不承诺继续；
- `completed`：完成条件全部满足；
- `cancelled`：决定不再完成原成果。

## 活跃项目最低要求

每个 `active` 项目都必须能够快速回答：

```text
预期成果是什么
完成条件是什么
当前状态是什么
下一步行动是什么
主要风险和依赖是什么
相关知识、来源和输出在哪里
```

`waiting` 项目必须记录等待对象和复查日期。`paused` 项目至少每月决定恢复、继续暂停或取消。

## 项目内容

可以保存：

- 项目主页；
- 里程碑、计划和决策；
- 项目专属实验、会议和实现记录；
- 尚未稳定的工作笔记；
- 输出草稿和交付物链接。

不长期复制：

- 已稳定的正式知识；
- 通用来源正文；
- 已发布输出的唯一副本；
- 长期责任标准。

## 完成、复盘与归档

项目进入 `completed` 或 `cancelled` 前完成最小复盘：

- 实际结果；
- 完成／取消原因；
- 关键决策；
- 可复用知识；
- 长期输出；
- 未完成事项去向；
- 责任领域是否需要更新。

复盘完成后整体移动到：

```text
90 档案/10 项目/<年份>/<项目名称>/
```

不使用“进行中／等待中／已完成”文件夹频繁搬动项目，状态始终由 Properties 表达。

## 回顾频率

- `active`：每周；
- `waiting`：按复查日期，至少每周查看；
- `paused`：每月；
- `planned`：每月清理；
- `completed`／`cancelled`：完成复盘后归档。
