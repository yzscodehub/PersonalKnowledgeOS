# 20 责任领域

责任领域是**没有明确结束日期，但需要长期维持一定标准的责任范围**。

它回答：

> 我需要长期对什么负责，并维持什么状态、标准或风险水平？

## 典型公开安全示例

- 职业与技术能力；
- 学习与知识管理；
- 内容创作与个人品牌；
- 数字设备与数据管理。

健康、财务、家庭等私人责任领域只有在仓库转为私有后才启用。

## 状态模型

```text
active
watch
at-risk
paused
retired
```

- `active`：按既定标准持续维护；
- `watch`：当前基本稳定，但需要重点观察；
- `at-risk`：低于标准或存在明确风险；
- `paused`：暂时不投入维护，但责任尚未结束；
- `retired`：责任永久结束，准备归档。

可选健康度：

```text
5  明显高于标准
4  达到标准
3  基本可接受
2  低于标准，需要项目修复
1  严重失衡，需要立即处理
```

健康度用于趋势判断，不追求精确量化。

## 责任领域主页最低要求

- 责任范围和非目标；
- 维护标准；
- 当前状态和健康度；
- 关键指标或观察信号；
- 例行维护；
- 风险和触发条件；
- 关联项目；
- 关联知识领域；
- 最近回顾和下一次回顾日期。

## 何时触发项目

出现以下情况时，建立项目而不是继续堆积在责任领域主页：

- 健康度持续低于 `3`；
- 需要一次性达到明确成果；
- 风险需要多步修复；
- 需要建立新系统、作品或能力；
- 例行维护无法解决问题。

项目完成后，更新责任领域的标准、状态、健康度或例行机制。

## 回顾与归档

- 活跃责任领域：每月回顾；
- 高风险领域：每周或按触发条件检查；
- 每季度检查维护标准是否仍合理；
- 永久结束时标记 `retired`，完成最终回顾后移动到 `90 档案/20 责任领域/`。

## 与知识领域的区别

- 责任领域回答“需要长期维护什么”；
- 知识领域回答“概念和技术属于哪套学科体系”；
- 数学、图形学和人工智能进入 `30 知识`；
- 职业能力、知识管理等长期责任进入这里。

## 术语

- Area = 责任领域
- Domain = 知识领域
- Module = 知识模块
- Topic = 知识主题
