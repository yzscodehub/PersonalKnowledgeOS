# 90 档案

档案保存**已经退出日常视图，但仍有历史、证据或恢复价值的内容**。

档案不是垃圾桶，也不是所有旧内容的默认去向。没有长期价值的内容直接删除。

## 可以归档

- 已完成、取消或长期停止的项目；
- 已退休的责任领域；
- 低频且不再维护的来源；
- 取消或退役的输出；
- 旧系统版本、迁移批次和历史设计；
- 特殊情况下退出知识网络的历史知识。

## 不应归档

- 只是暂时没有使用的稳定知识；
- 仍需要维护的责任领域；
- 正在等待外部事件的项目；
- 本应删除的低价值碎片；
- 私人、敏感或无权公开的历史文件。

## 目录建议

```text
90 档案/
├── 10 项目/
├── 20 责任领域/
├── 30 知识历史/
├── 40 来源/
├── 50 输出/
├── 60 日记与回顾/
└── 80 系统历史/
```

只在出现真实档案时创建对应目录。

## 归档前检查

- 最终状态已经明确；
- 项目或责任领域已经完成复盘；
- 稳定知识已经提炼；
- 长期输出已经移动到正式输出位置；
- 未完成事项已经转移；
- 隐私、版权和附件已经检查；
- 归档原因和日期可以追踪。

## 正式知识的特殊规则

正式知识通常保留原路径，不直接移动到档案。过时知识使用：

```yaml
lifecycle: deprecated
superseded_by:
  - "[[替代文章]]"
```

这样可以保护历史项目和旧链接。只有确认退出知识网络、但仍需要保留历史的特殊内容，才进入`30 知识历史`。

## 只读约定

归档内容原则上只读，允许的修改包括：

- 修复失效内部链接；
- 补充归档日期和原因；
- 增加恢复或替代关系；
- 修复隐私、版权和附件问题；
- 必要的格式迁移。

不得在档案目录中继续推进项目或维护日常正文。

## 恢复流程

1. 确认重新激活的原因；
2. 移动回原角色目录；
3. 更新状态、日期和下一步；
4. 检查链接、来源和附件；
5. 在档案索引中记录恢复位置和原因。
