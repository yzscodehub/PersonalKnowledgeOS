# Personal Knowledge Base v3 完整设计收敛计划

## 1. 目标

在 `design/knowledge-base-v3` 分支中完成整套个人知识库的详细设计，使合并后的 `main` 可以直接作为长期知识库基线，而不需要继续重构核心结构。

本阶段交付的是：

```text
完整架构
+ 详细规则
+ 可运行工作流
+ 领域蓝图
+ 自动化与治理
+ 迁移和运维方案
+ 最小验证样例
```

不要求提前写完所有知识正文。

## 2. 已完成基础

- [x] 顶层角色型目录；
- [x] 数学与图形学平级；
- [x] public-safe 公开仓库模式；
- [x] 责任领域与知识领域术语分离；
- [x] 多证据 verification；
- [x] 按声明类型选择来源；
- [x] 知识领域主归属规则；
- [x] map_kind 地图模型；
- [x] 最小 Frontmatter 和日期同步；
- [x] 附件、版权和大文件规则；
- [x] 顶层编号语义；
- [x] 数学—坐标—相机—投影试点；
- [x] Phase 1 试点复盘和自动校验。

# 4. D1：顶层信息角色详细设计

## 目标

让每个顶层目录都有清晰的进入条件、离开条件、状态模型、模板、回顾方式和归档规则。

## 工作项

- [x] `00 收件箱`：捕捉类型、处理时限、清理流程和失败保护；
- [x] `10 项目`：项目定义、状态机、成果、下一步、项目复盘和归档；
- [x] `20 责任领域`：维护标准、健康度、风险、例行检查和关联项目；
- [x] `30 知识`：正式知识准入、拆分、合并、成熟度和废弃；
- [x] `40 来源`：阅读状态、章节定位、提炼、引用和版权；
- [x] `50 输出`：草稿、发布、版本、平台适配和知识回流；
- [x] `60 日记与回顾`：日记、周回顾、月回顾和阶段复盘；
- [x] `90 档案`：归档条件、只读策略、恢复和历史链接；
- [x] 为每个角色补充示例、模板和边界案例；
- [x] 形成统一的信息归属决策树。

## 退出条件

任意一条新信息都能在一分钟内判断：放哪里、当前状态是什么、下一步是什么、何时归档。

# 6. D3：端到端工作流设计

必须完成并演练以下工作流：

- [ ] 快速捕捉 → 收件箱处理 → 正式归属；
- [ ] 书籍／论文阅读 → 来源笔记 → 正式知识；
- [ ] 学习路线 → 练习／实验 → 稳定知识；
- [ ] 项目问题 → 调研／实验 → 项目决策 → 知识回流；
- [ ] 故障排查 → 根因 → 修复验证 → 故障知识；
- [ ] 知识文章 → 输出草稿 → 平台发布 → 反向修订；
- [ ] 日记 → 周回顾 → 项目和责任领域更新；
- [ ] 过时内容 → needs-update → deprecated／superseded；
- [ ] 项目完成 → 复盘 → 输出和知识 → 档案；
- [ ] 旧内容 → 分类 → 迁移 → 校验 → 回滚。

每条工作流需要：

```text
触发条件
输入
步骤
状态变化
产物
异常处理
自动化点
退出条件
```

- [ ] 03 计算机科学；
- [ ] 04 图形学与渲染；
- [ ] 05 人工智能与数据科学；
- [ ] 06 软件工程；
- [ ] 07 系统与平台；
- [ ] 08 游戏引擎与实时应用；
- [ ] 09 音视频与多媒体；
- [ ] 10 嵌入式、机器人与智能驾驶；
- [ ] 11 设计、摄影与内容创作；
- [ ] 12 产品、商业与职业发展；
- [ ] 13 人文与社会科学；
- [ ] 99 跨领域知识地图。

每个领域蓝图包含：

```text
领域目标
主归属边界
一级模块
核心基础
典型应用
来源类型
实验或实践方式
核心 MOC
与其他领域的关系
首批建设建议
非目标
```

## 退出条件
