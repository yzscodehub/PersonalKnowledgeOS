# 08 游戏引擎与实时应用领域蓝图

## 1. 领域目标

维护具体游戏引擎、实时框架和交互式三维应用平台的对象模型、运行时、编辑器、资产、渲染集成、工具链和源码实践。

## 2. 主归属边界

进入本领域：

- UE5、Unity、Qt/QML、Three.js 等具体框架的结构和用法；
- 场景、对象、组件、ECS、编辑器、资产和序列化系统；
- 引擎中的渲染、动画、物理、UI、网络和脚本集成；
- 插件、模块、构建、打包、工具和源码阅读。

不进入本领域：

- 光栅化、PBR、RenderGraph 等通用渲染原理 → 图形学；
- ECS、任务图和并发的一般理论 → 计算机科学或软件工程；
- OS、驱动、编译器和平台故障 → 系统与平台；
- 物理规律和控制理论 → 物理与工程科学；
- 游戏设计和产品运营 → 设计或产品领域。

## 4. 核心基础

- 软件架构、模块、生命周期、反射和序列化；
- 图形学与渲染器架构；
- 并发、任务系统和实时调度；
- 资产格式、构建系统和版本控制；
- UI、输入和交互设计。

## 5. 典型应用

- UE5 游戏、可视化和虚拟制作；
- 智能驾驶、机器人和数字孪生界面；
- Qt/QML 跨平台三维桌面应用；
- Three.js 快速原型和 Web 三维展示；
- 编辑器、资产工具和技术美术管线；
- 引擎源码学习与定制渲染功能。

## 6. 来源与证据

优先来源：官方文档、对应版本源码、Release Notes、Sample、引擎 Trace、Frame Capture 和最小项目。

验证方式：

- 明确引擎和分支版本；
- 源码调用链、对象生命周期和线程检查；
- 最小可运行工程；
- Trace、Profiler 和 Frame Capture；
- 编辑器／运行时／打包环境对照；
- 升级前后兼容和回归测试。

## 7. 实验与实践

- 建立最小 UE5 C++／Blueprint 混合项目；
- 跟踪 Game→Render→RHI 数据流；
- 自定义材质、Pass、RDG 或插件；
- Qt/QML 与原生纹理桥接 Demo；
- Three.js 快速验证交互和视觉方案；
- 资产导入、Cook、缓存和依赖实验；
- 引擎版本升级和回归演练。

## 9. 跨领域关系

- ← 图形学：渲染算法、RHI、材质和 RenderGraph；
- ← 计算机科学：ECS、任务系统、网络和数据结构；
- ← 软件工程：模块、测试、构建、插件和质量；
- ← 系统平台：构建环境、驱动、打包和设备；
- ↔ 音视频：媒体播放、流送和同步；
- ↔ 机器人与智能驾驶：实时可视化和交互应用；
- ↔ 设计与内容：编辑器体验、UI、资产和叙事。

## 10. 首批建设建议

1. UE5 顶层对象、World、Actor、Component 和 Subsystem；
2. Game、Render、RHI 线程和渲染数据流；
3. UE5 材质、Pass、RDG 和 Renderer 结构；
4. ECS、资源、资产和编辑器系统；
5. Qt/QML 与 C++ 三维应用框架；
6. Three.js 快速原型和 WebGPU 应用；
7. 再扩展网络、动画、物理和发布。

## 11. 非目标

- 不把引擎源码描述当作通用图形学原理；
- 不为每个版本复制完整文章，使用版本字段和变更记录；
- 不只写编辑器点击步骤而缺少对象与生命周期；
- 不在没有最小工程验证时声称调用链正确；
- 不同时深挖所有引擎，优先围绕真实项目建立主线。
