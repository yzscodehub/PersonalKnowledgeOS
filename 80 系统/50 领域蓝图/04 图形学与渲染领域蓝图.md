# 04 图形学与渲染领域蓝图

## 1. 领域目标

维护视觉内容的表示、生成、变换、渲染、重建和显示知识，覆盖数学到渲染算法、GPU 实现、图形 API 映射、渲染器架构、性能验证和新型神经渲染方法。

## 2. 主归属边界

进入图形学：

- 几何表示与处理、相机、投影、可见性和光栅化；
- 纹理、颜色、光照、材质、PBR、阴影和全局光照；
- 渲染路径、RenderGraph、RHI、GPU-Driven 和渲染性能；
- 图形工作负载中的 Shader、GPU 架构和 API 应用；
- 光线追踪、离线渲染、神经和可微渲染。

不进入图形学：

- 与应用无关的线性代数和概率推导 → 数学；
- GPU 的一般体系结构和并行模型 → 计算机科学；
- DX12／Vulkan／Metal 安装、驱动和平台故障 → 系统与平台；
- UE5 Renderer 的具体源码和对象生命周期 → 游戏引擎；
- 图像生成模型的训练基础 → AI；
- 摄影构图和内容审美 → 设计与摄影。

## 4. 核心基础

- 数学：线性代数、几何、微积分、概率、采样和数值分析；
- 计算机科学：数据结构、体系结构、并行和计算几何；
- 物理：光学、辐射度量和材料模型；
- 软件工程：架构、测试、构建和性能方法；
- 系统平台：驱动、编译器、调试工具和设备能力。

## 5. 典型应用

- 实时游戏和引擎渲染；
- 智能驾驶、机器人和地图三维可视化；
- CAD、3D 打印、数字内容和可视化工具；
- 视频特效、虚拟制作和 AR／VR；
- 离线动画、路径追踪和产品渲染；
- 神经场景表示、重建和生成式三维内容。

## 6. 来源与证据

优先来源：图形学教材、SIGGRAPH／EGSR 等论文、API 规范、GPU 厂商文档、引擎源码、Frame Capture 和受控实验。

验证方式：

- 公式推导与参考实现；
- Golden Image、图像差异和可视化对照；
- RenderDoc／PIX／Xcode GPU Capture；
- GPU Counter、固定场景基准和质量比较；
- 跨 API、平台和驱动一致性检查；
- 生产场景中的稳定性和性能验证。

## 7. 实验与实践

- 最小软件光栅器和路径追踪器；
- 坐标、投影、深度、插值和采样实验；
- PBR、IBL、阴影、TAA 和后处理 Demo；
- DX12／Vulkan／Metal 的 RHI 对照实现；
- RenderGraph 资源生命周期实验；
- Frame Capture 和 GPU Counter 性能案例；
- NeRF／3DGS 小型复现与传统管线对比。

## 9. 跨领域关系

- ← 数学：所有几何、变换、采样和优化基础；
- ← 物理：光学、材料、动画和模拟；
- ← 计算机科学：GPU、并行、空间结构和编译；
- ↔ AI：神经渲染、生成、去噪和重建；
- ↔ 软件工程：模块化、测试、构建和性能治理；
- ↔ 系统平台：驱动、工具链、GPU 设备和部署；
- → 游戏引擎：具体引擎中的渲染应用；
- → 音视频：颜色、显示、视频纹理和 GPU 加速；
- → 机器人与智能驾驶：地图、点云、感知和 HMI 可视化。

## 10. 首批建设建议

1. 按已冻结范围完成 Phase 2 实时光栅化；
2. 建立纹理、采样、颜色和压缩基础；
3. 完成光照、材质与 PBR 最小闭环；
4. 建立 RenderGraph、RHI、Pass 和材质系统架构；
5. 用 DX12、Vulkan、Metal 做 API 映射；
6. 建立 GPU 性能、调试和回归案例；
7. 再扩展 GI、光追、体积和神经渲染。

## 11. 非目标

- 不按 API 平台复制一套图形学原理；
- 不把 UE5 或某个引擎源码作为全部图形学结构；
- 不只收集视觉效果而缺少机制、验证和性能；
- 不把摄影、视觉设计或 AI 训练基础混入图形学主干；
- 不在基础管线未闭环前同时扩展全部高级效果。
