# 06 软件工程领域蓝图

## 1. 领域目标

维护构建、测试、演进、协作和长期维护软件的通用工程方法，把计算机科学原理转化为可靠、可读、可验证和可交付的软件系统。

## 2. 主归属边界

进入软件工程：

- 需求、设计、架构、模块化和接口方法；
- 编码实践、测试、构建、依赖、版本控制和协作；
- 性能工程、可靠性、可观测性、安全工程和交付方法；
- 跨领域可复用的软件生命周期和质量治理。

不进入软件工程：

- 算法、操作系统和编译的一般理论 → 计算机科学；
- Windows、Linux、驱动、编译器安装和平台命令 → 系统与平台；
- 渲染器、播放器或机器人领域特有架构 → 对应领域主文章；
- UE5、Qt、Unity 的具体对象模型和源码 → 游戏引擎与实时应用。

## 3. 一级模块

| 代码 | 模块 | 范围 |
|---|---|---|
| SE-REQ | 需求与问题定义 | 目标、约束、验收、非目标和风险 |
| SE-DESIGN | 设计与建模 | 抽象、职责、接口、状态和数据流 |
| SE-ARCH | 软件架构 | 分层、组件、依赖、事件、插件和演进 |
| SE-CODE | 编程与代码组织 | 现代 C++、资源管理、错误处理和可读性 |
| SE-API | API 与契约设计 | 接口语义、版本、兼容、幂等和生命周期 |
| SE-TEST | 测试与验证 | 单元、集成、系统、属性、Golden 和回归 |
| SE-BUILD | 构建与依赖 | CMake、包管理、生成、缓存和可重复构建 |
| SE-VCS | 版本控制与协作 | Git、分支、PR、Review、发布和变更治理 |
| SE-QUALITY | 质量与可维护性 | 静态分析、代码审查、技术债和重构 |
| SE-PERF | 性能工程 | 基准、剖析、数据布局、延迟和吞吐优化 |
| SE-REL | 可靠性与容错 | 故障模型、恢复、降级、重试和状态一致性 |
| SE-OBS | 调试与可观测性 | 日志、指标、Trace、诊断和事故分析 |
| SE-SEC | 安全工程 | 安全需求、边界、输入验证、依赖和密钥实践 |
| SE-DELIVERY | 交付与运行 | CI/CD、配置、环境、发布策略和回滚方法 |

## 4. 核心基础

- 计算机科学中的抽象、状态、并发和复杂度；
- 清晰的问题定义和验收标准；
- 模块职责、数据所有权和生命周期；
- 测试、版本控制和可重复构建；
- 失败路径、可观测性和回滚能力。

## 5. 典型应用

- 跨平台渲染器、播放器和 RHI；
- C++／Qt／QML 桌面应用；
- AI、RAG 和 Agent 应用系统；
- 音视频、WebRTC 和异步媒体管线；
- 机器人、智能驾驶和嵌入式上层软件；
- 个人知识库的自动化、迁移和发布工具。

## 6. 来源与证据

优先来源：工程经典著作、语言标准、官方文档、成熟开源项目、设计记录和生产事故报告。

验证方式：

- 可执行测试和静态分析；
- 架构约束检查；
- 基准、剖析和回归对比；
- 故障注入、恢复和回滚演练；
- 真实项目中的维护成本和变更数据；
- Code Review 和设计评审。

## 7. 实验与实践

- 小型跨平台库和分层架构；
- 资源生命周期、错误传播和并发实验；
- 测试金字塔、Golden Image 和属性测试；
- 构建缓存、依赖锁定和可重复构建；
- 性能基准与数据布局对比；
- 故障注入、日志和恢复演练；
- PR、ADR 和版本发布流程实践。

## 8. 核心 MOC

计划维护：

```text

现代 C++ 与资源生命周期 MOC
架构、模块与依赖 MOC

测试、验证与回归 MOC
构建、依赖与交付 MOC
性能工程与可观测性 MOC
可靠性、故障与恢复 MOC
Git、协作与发布 MOC
```

## 9. 跨领域关系

- ← 计算机科学：算法、并发、操作系统和语言理论；
- ↔ 系统平台：具体环境、工具链和部署；
- → 图形学：渲染器模块、RHI、RenderGraph 和测试方法；
- → AI：RAG、Agent、Serving 和评估工程；
- → 游戏引擎：插件、模块、资产和工具开发；
- → 音视频／机器人：异步管线、资源生命周期和可靠性。

领域特有架构放领域主文章，通用工程模式回流软件工程。

## 10. 首批建设建议

1. 现代 C++ 对象、内存和资源生命周期；
2. 模块、接口、依赖和跨平台架构；
3. 测试、错误处理和可观测性；
4. CMake、依赖管理和可重复构建；
5. 性能基准、剖析和回归；
6. Git、PR、ADR、发布和回滚；
7. 再扩展可靠性、安全和交付体系。

## 11. 非目标

- 不把所有代码示例都归为软件工程；
- 不复制具体平台命令和引擎源码说明；
- 不只记录设计模式名称而缺少问题和权衡；
- 不用统一模板强迫所有系统采用同一架构；
- 不把未经真实变更验证的“最佳实践”写成绝对规则。
