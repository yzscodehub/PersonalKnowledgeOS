# 个人知识库设计说明 v3.0

## 1. 系统定位

本知识库是一套个人知识操作系统，而不是资料分类仓库。它需要同时支持捕捉、学习、研究、工程实践、项目管理、内容输出和长期维护。

## 2. 三层模型

```text
行动层：项目 / 领域 / 输出 / 日记
知识层：数学 / 计算机科学 / 图形学 / AI / 软件工程等
证据层：书籍 / 论文 / 官方文档 / 代码 / 实验
```

## 3. 顶层结构

顶层目录按信息角色划分：收件箱、项目、领域、知识、来源、输出、日记、系统和档案。主题分类只在 `30 知识` 中展开。

## 4. 核心边界

### 项目

有明确成果和结束条件，管理生产过程。

### 领域

需要长期维护标准的责任范围。

### 知识

经过理解、重组和验证，可复用的认知内容。

### 来源

知识的出处与证据，不作为正式知识正文。

### 输出

面向他人的最终交付物。

## 5. 组织机制

- 文件夹：稳定主归属；
- Properties：动态状态；
- MOC：学习顺序和多视角知识地图；
- Manifest：建设计划、优先级和未实例化主题；
- 内部链接：前置、应用、对比、实现和来源关系；
- Git：版本、审阅和历史追踪。

## 6. 知识唯一解释规则

一个稳定概念只有一个完整基础解释，但允许创建面向不同问题的领域应用文章。

例如：

```text
数学/矩阵作为线性映射
图形学/Model、View 与 Projection 矩阵
UE5/FMatrix 与 FTransform
```

三篇文章分别解决数学本体、图形应用和引擎实现问题。

## 7. 状态模型

### 内容成熟度

`seed → outline → draft → stable → evergreen`

### 验证状态

`unverified / source-checked / derived / experiment-reproduced / production-validated`

### 生命周期

`active / needs-update / deprecated / archived`

这三个维度分别维护，不合并成一条线性状态。

## 8. 第一阶段试点

以两本图形学书作为来源，建设 20～30 篇主干文章：

- 数学：向量、基、坐标、标架、矩阵、仿射空间、齐次坐标、旋转与四元数；
- 图形学：坐标空间、观察变换、投影、Clip Space、NDC、视口、帧流程、光栅化、深度；
- 实验：矩阵约定、投影映射、深度精度和透视正确插值。

## 9. 迁移原则

1. 先移动和建立映射，不急于全量重写；
2. 先修复链接和主归属，再扩充内容；
3. 保留旧文章 ID 到 `legacy_id`；
4. 未开始主题只登记在 Manifest；
5. 试点通过后再扩展全库。
