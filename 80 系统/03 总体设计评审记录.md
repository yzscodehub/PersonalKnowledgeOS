# 个人知识库总体设计评审记录

> 本文记录对 [[80 系统/01 知识库设计说明|个人知识库总体设计方案 v3.7]] 和 [[80 系统/02 实施路线图|实施路线图]] 的 Gate A 评审。结论为“有条件通过”：总体方向正确，但在剩余治理规则冻结前，不进入 Phase 2。

# 1. 总体结论

当前方案已经具备长期个人知识库所需的主要骨架：

- 顶层按信息角色划分，而不是把项目、书籍、数学和日记混在同一维度；
- 数学与图形学平级，基础理论可以被 AI、机器人和音视频复用；
- 来源、正式知识、项目、实验和输出形成可追溯闭环；
- 文件夹、Properties、MOC、Manifest 和 Git 的职责基本清晰；
- 采用小规模试点和阶段门禁，避免一次性全量重构。

当前不建议推翻方案，但 Gate A 仍有若干决策需要完成。

# 2. 已解决决策

## F-01：公开仓库采用 public-safe 模式

### 决策

当前仓库继续保持公开，但只允许保存可公开的技术知识、来源笔记、实验、技术项目和输出。健康、财务、私人日记、身份信息、真实雇佣资料、凭据和无权公开的附件不得提交。

未来需要长期保存私人内容时，必须在写入前将仓库改为私有。

### 状态

`accepted`

关联规则：

- [[80 系统/10 治理规则/公开仓库与隐私规则|公开仓库与隐私规则]]
- [[80 系统/60 ADR/ADR-0004-公开仓库采用公开安全模式|ADR-0004：公开安全模式]]

## F-02：责任领域命名已确认

### 决策

顶层目录已从：

```text
20 领域
```

调整为：

```text
20 责任领域
```

统一术语：

- Area = 责任领域；
- Domain = 知识领域；
- Module = 知识模块；
- Topic = 知识主题。

该调整解决了 PARA 长期责任与数学、图形学、AI 等知识领域之间的中文语义冲突。

### 状态

`accepted`

关联决策：[[80 系统/60 ADR/ADR-0005-责任领域命名|ADR-0005：责任领域命名]]。

# 3. 新增已解决决策

## F-03：verification 使用多证据列表

### 决策

`verification` 改为可累积的 YAML 列表：

```yaml
verification:
  - source-checked
  - derived
  - experiment-reproduced
```

尚无证据时使用 `verification: []` 或省略字段。`unverified` 不再作为证据值。成熟度和生命周期继续使用单值。

Frontmatter 只记录证据类型；正文需要链接具体来源、推导、实验或生产记录。

### 状态

`accepted`

关联决策：[[80 系统/60 ADR/ADR-0006-verification使用多证据列表|ADR-0006：verification 使用多证据列表]]。

# 4. 新增已解决决策

## F-04：按声明类型选择证据

### 决策

不建立跨所有问题的统一来源权威排序，改为按声明类型选择证据。数学、API 规范、研究算法、版本实现、性能和工程经验分别使用与其性质匹配的首选证据。

规范语义、实现行为和实验观察必须分开记录；来源冲突时保留差异、版本、环境和适用范围。

### 状态

`accepted`

关联决策：[[80 系统/60 ADR/ADR-0007-按声明类型选择证据|ADR-0007：按声明类型选择证据]]。

# 5. 重要优化项

## F-05：知识领域边界和主归属规则已冻结

### 决策

正式建立 `01`～`13` 知识领域职责表，并采用“一个主归属＋应用文章＋跨领域 MOC”的组织方式。

通用理论放最基础领域；图形学、AI、音视频、平台、引擎和业务领域只展开各自上下文、实现和失败条件。

### 状态

`accepted`

关联决策：[[80 系统/60 ADR/ADR-0008-知识领域边界与主归属|ADR-0008：知识领域边界与主归属]]。

## F-06：地图类笔记职责已区分

### 决策

地图类页面统一使用 `type: map`，通过 `map_kind` 区分 `moc`、`learning-route`、`index` 和 `dashboard`。

MOC 表达主题网络，学习路线表达目标顺序，索引提供查找入口，仪表盘展示动态状态；Manifest 继续独立管理建设计划。

### 状态

`accepted`

关联决策：[[80 系统/60 ADR/ADR-0009-map_kind区分地图类笔记|ADR-0009：map_kind 区分地图类笔记]]。

---

## F-07：最小 Frontmatter 和日期策略已确认

### 决策

正式知识只强制 `id`、`type`、`domain`、`maturity`、`lifecycle`；地图、来源和项目采用各自最小字段。验证、来源、平台版本和迁移字段按条件填写。

模板写入日期，`scripts/sync_note_dates.py --staged` 自动维护暂存笔记的 `updated`；日期不再作为知识语义必填字段。

### 状态

`accepted`

关联决策：[[80 系统/60 ADR/ADR-0010-最小Frontmatter与日期自动化|ADR-0010：最小 Frontmatter 与日期自动化]]。

---

## F-08：公开仓库需要来源文件、附件和版权策略

当前 public-safe 规则已经覆盖隐私红线，后续还需进一步明确：

- 不把受版权保护的整本书籍提交到公开仓库；
- 来源笔记保存书目信息、章节定位和个人重述；
- 引用只使用必要的短摘录，并记录页码；
- `_assets` 只保存有权公开的图片、自己生成的图和许可明确的素材；
- 大文件采用 Git LFS、外部存储或不入库策略。

---

## F-09：顶层编号 `70` 的空缺需要说明

当前从 `60` 跳到 `80`。应明确：

- `70` 是刻意保留的扩展槽；或
- 不承诺编号连续，`80 系统` 和 `90 档案` 是语义固定编号。

避免未来为了“填满编号”随意增加顶层目录。

# 7. PR 和阶段建议

当前 PR 同时包含架构基线和第一批试点内容，严格来说混合了设计与内容。

由于仓库此前几乎为空，试点内容用于证明设计能够运行，因此可以将它视为一次性的 Bootstrap 例外，不必为了形式纯度重做提交历史。

建议：

1. 继续解决 F-03～F-09；
2. 完成 Gate A 评审；
3. 在当前 PR 中完成 Phase 1 试点复盘，而不是继续增加 Phase 2 正文；
4. 将当前 PR 作为 `v0.2.0-design-baseline` 合并；
5. 后续光栅化、PBR、API 和迁移分别使用独立内容 PR。
