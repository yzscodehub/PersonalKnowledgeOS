# D3 端到端工作流设计

## 1. 目标

D3 负责把 D1 的信息角色和 D2 的知识对象连接为可执行流程。任何重要信息都不应只停留在某个目录中，而应能够从输入经过处理、验证和回流，形成明确的长期产物。

每条工作流统一描述：

```text
触发条件
输入
执行步骤
状态变化
产物
异常与停止条件
自动化点
退出条件
```

D3 冻结流程和交接边界，但不要求现在批量生产知识正文，也不执行旧库全量迁移。

---

# 2. 通用工作流原则

## 2.1 主对象和主状态

每次执行工作流都必须确定一个主对象：

- 捕捉工作流的主对象是收件箱条目；
- 阅读工作流的主对象是来源笔记；
- 学习工作流的主对象是学习路线或学习项目；
- 工程问题工作流的主对象是项目；
- 故障工作流的主对象是故障问题，稳定后转为正式故障文章；
- 输出工作流的主对象是输出主页；
- 回顾工作流的主对象是时间型回顾笔记；
- 过时知识工作流的主对象是正式知识文章；
- 项目归档工作流的主对象是项目主页；
- 迁移工作流的主对象是迁移批次。

状态只记录在主对象或对应 Manifest 中，不在多个页面重复维护。

## 2.2 交接规则

对象从一个角色进入另一个角色时，优先使用以下方式：

1. 在目标角色创建或更新正式对象；
2. 在原对象记录目标链接和处理结论；
3. 删除临时空壳，或保留有历史价值的过程记录；
4. 更新 Manifest、MOC、来源反向链接或项目输出；
5. 运行校验。

“回流”不是复制全文，而是把稳定结论、状态、证据或成果写回其唯一主位置。

## 2.3 最小执行记录

复杂工作流可以使用 [[80 系统/20 模板/工作流执行记录模板|工作流执行记录模板]]。简单工作流直接在项目、来源、输出或回顾主页中记录，不额外制造重复文档。

## 2.4 自动化边界

自动化可以：

- 检查状态和必填字段；
- 发现失效链接、遗漏回流和路径不一致；
- 生成候选列表和提醒；
- 运行实验、测试和公开安全检查。

自动化不能替代：

- 信息归属判断；
- 来源是否真正支持结论的判断；
- 根因分析；
- 项目完成和知识成熟度的人工决策；
- 隐私、版权和发布风险判断。

# 3. WF-001 快速捕捉 → 收件箱处理 → 正式归属

## 触发条件

出现值得暂时保留、但无法立即完成归属或处理的信息。

## 输入

- 问题、想法、观察或行动线索；
- URL、书目、截图或对话摘要；
- 项目、知识、来源或输出候选；
- 暂时缺少上下文的信息。

## 执行步骤

1. 使用收件箱条目记录最小原始内容；
2. 补充一句“我保留它，是为了什么”；
3. 检查公开安全，敏感内容不入库；
4. 判断是否需要补充上下文，必要时进入 `clarify`；
5. 按信息归属决策树选择唯一主角色；
6. 在目标位置创建或更新正式对象；
7. 记录分流结果和下一步；
8. 删除或移动原捕捉条目。

## 状态变化

```text
unprocessed → clarify → routed
           ↘ discarded
```

## 产物

以下之一：项目、责任领域更新、知识主题、来源笔记、输出草稿、时间记录、档案或删除决定。

## 异常与停止条件

- 缺少上下文：保持 `clarify`，但必须记录需要补充什么；
- 只有裸链接：补标题和用途，否则删除；
- 连续两次周回顾仍无法判断：默认删除或改写为明确问题；
- 涉及凭据、私人或雇佣机密：不进入公开仓库。

## 自动化点

- 仪表盘列出超过 7 天未处理条目；
- 超过 30 天条目产生警告；
- 检查 `routed` 条目是否仍长期滞留；
- 检查收件箱条目是否缺少标题和用途。

## 退出条件

条目已进入唯一主归属，或明确删除；收件箱不保留无用空壳。

# 4. WF-002 书籍／论文阅读 → 来源笔记 → 正式知识

## 触发条件

需要通过书籍、论文、规范、文档、源码或课程回答一个明确问题。

## 输入

- 阅读问题；
- 来源版本、章节或提交；
- 相关项目、学习路线或知识缺口；
- 权利和存储信息。

## 执行步骤

1. 创建或复用来源笔记，记录版本和阅读目的；
2. 明确来源可以支持的声明类型；
3. 建立章节、页码、URL 或源码定位；
4. 记录重要结论、限制、冲突和待验证问题；
5. 判断内容仍属于来源摘要，还是已经形成可复用知识；
6. 在 Manifest 登记新知识主题，检查是否已有主解释；
7. 创建或更新正式知识文章；
8. 为 `source-checked` 核对来源是否真正支持正文结论；
9. 在来源笔记反向链接已提炼文章；
10. 完成本轮阅读目标后将来源设为 `processed` 或 `reference`。

## 状态变化

来源：

```text
unread → reading → processed
   ↘        ↘
 reference  abandoned
```

知识：

```text
planned（Manifest）→ seed → outline → draft
```

## 产物

- 具有定位和限制的来源笔记；
- 新建或修订的正式知识；
- 待验证问题；
- 来源与知识双向链接；
- 必要的实验或项目候选。

## 异常与停止条件

- 来源不支持目标声明：不得标记 `source-checked`；
- 多个可靠来源冲突：保留各自条件，不强行合并；
- 只完成摘录、未重组解释：保留在来源，不创建空知识文章；
- 来源质量不足：降为补充证据或停止处理；
- 无权公开原始文件：只保存书目信息和个人重述。

## 自动化点

- 检查 `source-checked` 文章是否具有来源；
- 检查来源笔记是否反向链接提炼文章；
- 检查版本敏感来源是否记录版本；
- 检查来源状态与阅读进度是否明显矛盾。

## 退出条件

阅读问题得到回答，来源定位和限制清楚，稳定结论进入正式知识，未解决问题有明确去向。

# 5. WF-003 学习路线 → 练习／实验 → 稳定知识

## 触发条件

为了达到明确能力目标，需要按顺序学习一组知识，并通过练习或实验检验理解。

## 输入

- 学习目标和完成标准；
- 学习路线；
- 前置 MOC 和知识文章；
- 练习、实验或实现环境；
- 可用时间和当前能力基线。

## 执行步骤

1. 选择或创建 `map_kind: learning-route` 的学习路线；
2. 明确受众、目标、阶段和完成标准；
3. 检查路线链接的是已有知识还是 Manifest 计划主题；
4. 逐阶段阅读知识和来源，记录尚未理解的问题；
5. 完成练习、推导、最小实现或实验；
6. 将结果记录到实验文章、实现文章或项目记录；
7. 修正错误理解和知识文章；
8. 只有证据匹配时才增加 `derived` 或 `experiment-reproduced`；
9. 达到文章成熟度条件后升级 `maturity`；
10. 更新学习路线的阶段说明，但不在路线中维护个人完成状态的唯一副本。

## 状态变化

```text
知识：seed → outline → draft → stable
实验：seed → draft → stable
路线：outline → draft → stable
```

个人进度记录在项目、日记或执行记录中，不写入通用路线的永久结构。

## 产物

- 经过练习或实验修正的知识；
- 实验、实现或推导记录；
- 学习路线改进；
- 新的前置知识或应用文章候选；
- 能力目标的完成或差距判断。

## 异常与停止条件

- 路线过长且无输出：拆为阶段项目；
- 只阅读无验证：不能据此将知识升级为 `stable`；
- 练习结果与正文冲突：优先回到约定、代码和来源核查；
- 学习目标变化：建立新路线或项目，不破坏通用路线；
- 前置缺失：回退到前置阶段，不提前创建空文章。

## 自动化点

- 检查路线链接是否有效；
- 检查 Manifest 依赖是否存在；
- 运行实验和单元测试；
- 标记路线中的 `planned` 主题和缺失实体；
- 检查稳定实验是否具有复现证据。

## 退出条件

能力目标达到定义的完成标准；相关知识、实验和路线互相链接，并能被他人或未来自己重复使用。

# 6. WF-004 项目问题 → 调研／实验 → 项目决策 → 知识回流

## 触发条件

活跃项目出现会影响设计、实现、质量或进度的问题，且需要多步调研或验证。

## 输入

- 项目目标和约束；
- 当前问题、影响和决策截止时间；
- 已有知识与来源；
- 候选方案；
- 实验、性能或实现环境。

## 执行步骤

1. 在项目主页或决策记录中描述问题和决策边界；
2. 区分项目专属问题和可复用知识问题；
3. 检查知识库中是否已有主解释；
4. 收集与声明类型匹配的来源；
5. 必要时建立最小实验、原型或性能测试；
6. 比较候选方案、风险、成本和适用条件；
7. 在项目中记录决策、日期、原因和未选方案；
8. 将通用结论提炼到正式知识、实现、比较或实验文章；
9. 把项目特定参数和取舍留在项目中；
10. 更新项目下一步、风险、交付物和责任领域。

## 状态变化

项目：

```text
active → waiting（外部依赖）→ active
active → paused（主动停止）
```

知识按实际完成度从 `seed` 向 `draft/stable` 演进。

## 产物

- 可追踪的项目决策；
- 调研、实验或性能结果；
- 通用知识回流；
- 项目下一步和风险更新；
- 必要的后续项目或来源队列。

## 异常与停止条件

- 决策时间不足：记录临时决策、风险和复查条件；
- 实验环境不可靠：结论保持 `draft`，不得推广；
- 结论只适用于当前项目：不创建通用知识文章；
- 调研无限扩展：以决策所需最小证据为停止条件；
- 项目机密：只保留可公开的抽象知识，不提交敏感细节。

## 自动化点

- 检查活跃项目是否有下一步；
- 检查 `waiting` 项目是否有等待对象和复查日期；
- 自动运行实验和测试；
- 检查项目中链接的正式知识是否存在；
- 项目完成前提示知识和输出回流检查。

## 退出条件

项目已有明确可执行决策，证据与风险可追踪，通用结论已经回流到唯一正式位置。

# 7. WF-005 故障排查 → 根因 → 修复验证 → 故障知识

## 触发条件

出现可重复或高影响的异常、性能退化、崩溃、错误结果或系统不稳定。

## 输入

- 症状和影响范围；
- 平台、版本、环境和时间线；
- 日志、抓帧、Counter、转储或错误码；
- 预期结果；
- 最近变更和可疑依赖。

## 执行步骤

1. 先保护数据、服务和项目进度；
2. 建立最小问题记录，明确环境和版本；
3. 尝试稳定复现，无法复现时记录观察条件；
4. 建立假设表，分别记录支持和反对证据；
5. 逐步缩小变量，保留关键排除路径；
6. 区分根因修复、缓解措施和经验性修复；
7. 实施修复并运行回归验证；
8. 记录适用版本、副作用和监控信号；
9. 判断是否值得形成正式 `troubleshooting` 文章；
10. 把通用原理链接到 concept/system/implementation，而不是复制全文。

## 状态变化

故障记录：

```text
observed → reproducing → diagnosing → fixed → verified
                         ↘ mitigated
                         ↘ unresolved
```

正式故障文章仍使用知识成熟度和验证证据。

## 产物

- 根因或明确的经验性边界；
- 修复、缓解和回归结果；
- 稳定故障文章；
- 监控和预防措施；
- 相关实现或系统知识修正。

## 异常与停止条件

- 无法稳定复现：标记 `unresolved`，不伪造根因；
- 只有临时绕过：标记 `mitigated`，保留复查条件；
- 版本差异明显：分别记录环境，不推广为普遍规律；
- 调试日志含敏感信息：先脱敏再入库；
- 排查成本超过影响：记录停止理由和监控方案。

## 自动化点

- 运行最小复现、单元测试和回归测试；
- 收集版本、环境和日志摘要；
- 检查稳定故障文章是否具有修复验证；
- 检查 `production-validated` 是否链接生产或项目记录；
- 提醒版本敏感故障复核。

## 退出条件

故障已修复并验证，或明确进入缓解／未解决状态；结论、边界和后续监控可追踪。

# 8. WF-006 知识文章 → 输出草稿 → 平台发布 → 反向修订

## 触发条件

一组知识已经足以面向明确受众形成文章、视频、教程、演示或其他交付物。

## 输入

- 目标受众和发布目的；
- 正式知识文章；
- 关键来源和验证证据；
- 输出形式、平台和限制；
- 相关项目或截止时间。

## 执行步骤

1. 创建输出主页，定义受众、用途和核心信息；
2. 选择规范主版本，避免平台成为唯一副本；
3. 链接使用的知识和来源；
4. 根据媒介组织叙事，不复制知识库结构；
5. 核对事实、引用、隐私和版权；
6. 进入 `review`，检查结构、表达和平台约束；
7. 达到发布条件后设为 `ready`；
8. 发布或交付，记录版本、日期、平台和链接；
9. 收集反馈、问题和表现；
10. 把事实修正、解释改进和知识缺口回流到正式知识、来源或新项目。

## 状态变化

```text
idea → draft → review → ready → published
  ↘                         ↘
 cancelled                  retired
```

## 产物

- 可维护的输出主版本；
- 平台变体；
- 发布记录和反馈；
- 正式知识修正；
- 新知识主题或后续项目。

## 异常与停止条件

- 知识尚不稳定：输出可以是探索性内容，但必须明确不确定性；
- 平台限制导致事实丢失：保留主版本和必要说明；
- 发布后发现事实错误：先修正式知识，再同步输出；
- 无权使用素材：替换、自制或删除；
- 输出价值不足：设为 `cancelled`，不因已投入时间而继续。

## 自动化点

- 检查输出是否链接知识和来源；
- 检查发布前公开安全和附件；
- 检查版本、平台和发布记录；
- 生成平台格式候选，但人工确认；
- 提醒 `published` 输出处理反馈和知识回流。

## 退出条件

输出已发布、取消或退役；发布记录完整，重要反馈已经回流到正式系统。

# 9. WF-007 日记 → 周回顾 → 项目和责任领域更新

## 触发条件

日常工作、学习和生活过程中产生时间型记录，需要定期从过程提炼行动和稳定结论。

## 输入

- 每日笔记；
- 收件箱条目；
- 项目状态；
- 责任领域健康度和风险；
- 来源、知识和输出变化；
- 自动化警告。

## 执行步骤

1. 每日记录当天重点、进展、阻塞和待提炼内容；
2. 行动尽快进入项目，不等待周末；
3. 周回顾清理收件箱；
4. 检查每个活跃项目是否有下一步；
5. 检查等待、暂停和完成项目；
6. 更新责任领域状态、健康度、风险和触发项目；
7. 处理来源阅读和知识待验证事项；
8. 更新输出状态和发布反馈；
9. 归档完成内容并运行校验；
10. 确定下一周不超过三项重点。

## 状态变化

- 每日笔记完成后保留时间记录；
- 周回顾 `open → completed`；
- 项目、责任领域、来源、知识和输出在各自主位置更新。

## 产物

- 清理后的收件箱；
- 项目下一步和等待复查日期；
- 责任领域风险和新项目；
- 提炼的知识、来源和输出；
- 下周重点；
- 已归档或删除内容。

## 异常与停止条件

- 周回顾过长：优先收件箱、活跃项目和高风险责任领域；
- 连续漏做：恢复时只处理当前状态，不补写所有历史细节；
- 同时活跃项目过多：暂停或取消低价值项目；
- 回顾只写总结、不更新正式对象：视为未完成；
- 维护成本过高：减少指标和低价值检查。

## 自动化点

- 生成活跃项目、等待项目、待验证知识和阅读来源视图；
- 标记超期收件箱和无下一步项目；
- 检查回顾是否仍为 `open`；
- 运行结构、附件、Manifest 和实验校验。

## 退出条件

关键变化已经写回正式对象，收件箱和活跃项目可控，下周重点清楚，周回顾设为 `completed`。

---

# 10. WF-008 过时内容 → needs-update → deprecated／superseded

## 触发条件

来源、规范、API、平台、产品、实验或工程实践发生变化，使现有知识可能不再准确或适用。

## 输入

- 新版本或新来源；
- 冲突证据；
- 自动化提醒；
- 项目或输出中的失败反馈；
- 被替代的算法、API 或实现。

## 执行步骤

1. 将文章 `lifecycle` 设为 `needs-update`；
2. 记录触发原因、影响范围和版本；
3. 区分事实错误、版本变化、范围变化和更优替代；
4. 收集新证据并重新验证；
5. 可以修正原文章时，更新正文并恢复 `active`；
6. 核心问题已经改变时，创建新主文章；
7. 将旧文章设为 `deprecated`；
8. 使用 `superseded_by` 列表指向替代文章；
9. 保留历史语义、适用版本和迁移说明；
10. 更新 MOC、索引、学习路线、Manifest 和相关输出。

## 状态变化

```text
active → needs-update → active
                    ↘ deprecated → archived（少见）
```

## 产物

- 修正后的活跃文章，或新主文章与替代页；
- 新来源和验证证据；
- 更新后的导航和输出；
- 版本迁移说明。

## 异常与停止条件

- 新证据尚不充分：保持 `needs-update`，明确不确定部分；
- 只有标题或目录变化：保留 ID，不视为知识废弃；
- 仍有历史用户依赖旧语义：不得直接删除；
- 多个替代目标：`superseded_by` 可以是列表，并说明选择条件；
- 没有替代文章：在正文说明原因，校验允许明确例外。

## 自动化点

- 检查 `deprecated` 是否有 `superseded_by` 或无替代说明；
- 检查版本敏感文章的复核日期；
- 检查导航是否仍指向废弃文章；
- 检查 ID、别名和旧链接；
- 生成 `needs-update` 仪表盘。

## 退出条件

文章已经恢复准确并回到 `active`，或完成可追踪的废弃和替代；相关导航与输出不再误导。

---

# 11. WF-009 项目完成 → 复盘 → 输出和知识 → 档案

## 触发条件

项目完成条件已经满足，或项目被取消且需要退出日常视图。

## 输入

- 项目主页和完成条件；
- 里程碑、决策、实验和实现记录；
- 输出草稿和交付物；
- 未完成事项；
- 关联责任领域。

## 执行步骤

1. 对照完成条件，决定 `completed` 或 `cancelled`；
2. 记录实际结果和偏差；
3. 提取关键决策、可复用知识和故障经验；
4. 将稳定内容写入正式知识、实验、实现或故障文章；
5. 将长期交付物移动或链接到 `50 输出`；
6. 把未完成事项转入新项目、责任领域或删除；
7. 更新关联责任领域的状态、标准和风险；
8. 完成项目复盘；
9. 检查隐私、附件和链接；
10. 移动到 `90 档案/10 项目/<年份>/`。

## 状态变化

```text
active / waiting / paused → completed
                          ↘ cancelled
```

归档不再改变项目最终状态。

## 产物

- 完整项目复盘；
- 正式知识和输出；
- 责任领域更新；
- 未完成事项的明确去向；
- 可恢复的项目档案。

## 异常与停止条件

- 完成条件未满足但不再继续：标记 `cancelled`，不要伪装完成；
- 项目含未整理敏感材料：先清理再归档；
- 项目知识尚不稳定：保留项目记录，知识文章维持真实成熟度；
- 输出仍在维护：保留在 `50 输出`，不随项目归档；
- 归档后重新启动：恢复到项目目录并更新状态。

## 自动化点

- 检查完成／取消项目是否有复盘；
- 检查未完成事项和输出链接；
- 检查档案路径、归档日期和最终状态；
- 检查项目引用的知识和来源是否有效；
- 生成归档候选列表。

## 退出条件

项目退出活跃视图，复盘、知识、输出和后续事项均有唯一去向，档案可读且可恢复。

---

# 12. WF-010 旧内容 → 分类 → 迁移 → 校验 → 回滚

## 触发条件

需要把旧知识库、旧目录或历史笔记批次转换到 v3 结构。

## 输入

- 旧库只读备份；
- 文件、链接、ID、附件和类型统计；
- 目标领域蓝图和主归属规则；
- 迁移批次范围；
- 回滚点和验收标准。

## 执行步骤

1. 冻结旧库或建立只读快照；
2. 建立迁移清单，记录旧路径、类型、链接和附件；
3. 自动生成候选分类，但由人工确认主归属；
4. 检查重复文章和已有主解释；
5. 为保留文章分配或复用稳定 ID；
6. 使用 `legacy_ids` 保存旧标识；
7. 重写 Frontmatter、链接和来源关系；
8. 处理版权、隐私和附件；
9. 在独立迁移分支提交小批次；
10. 运行结构、链接、Manifest、附件和领域校验；
11. 人工抽查语义和可读性；
12. 验收后标记批次完成，失败则回滚到批次前提交。

## 状态变化

迁移批次：

```text
planned → inventory → classified → transforming → validating → accepted
                                                  ↘ rolled-back
                                                  ↘ paused
```

单篇知识根据真实完成度进入 `seed/outline/draft/...`，不能因搬迁自动升级成熟度。

## 产物

- 可重复的迁移清单和映射；
- 新结构中的正式对象；
- `legacy_ids` 和旧链接关系；
- 附件处理记录；
- 批次校验报告和回滚记录；
- 旧库只读归档。

## 异常与停止条件

- 重复率、失效链接或版权风险超过批次阈值：暂停；
- 无法判断主归属：保留在迁移清单，不强行落库；
- 自动转换改变语义：回滚并改为人工处理；
- 旧内容价值过低：记录删除决定，不为迁移而迁移；
- 批次超过 50 篇：拆小，避免审查和回滚困难。

## 自动化点

- 统计旧文件、链接、标题、ID 和附件；
- 生成分类和重复候选；
- 检查新旧路径和 `legacy_ids`；
- 运行所有 CI；
- 生成迁移差异和回滚命令；
- 记录批次指标。

## 退出条件

批次通过人工和自动校验，可以独立回滚；旧内容不是简单搬家，而是完成主归属、去重、证据和链接转换。

# 13. 十条工作流的协作关系

```text
捕捉 WF-001
   ├─→ 来源阅读 WF-002 ─→ 学习验证 WF-003
   ├─→ 项目问题 WF-004 ─→ 故障处理 WF-005
   ├─→ 输出发布 WF-006
   └─→ 日记回顾 WF-007

所有正式知识
   └─→ 过时与替代 WF-008

所有项目
   └─→ 完成与归档 WF-009

旧知识库
   └─→ 迁移与回滚 WF-010
```

工作流可以互相触发，但每次只确定一个主对象和一个当前出口，避免一条记录同时维护多个状态。

---

# 14. 工作流优先级与运行节奏

## 日常

- WF-001 快速捕捉；
- WF-004 项目问题；
- WF-005 故障排查；
- WF-007 每日记录。

## 每周

- WF-007 周回顾；
- 检查 WF-002 阅读队列；
- 检查 WF-004 活跃项目和等待项；
- 检查 WF-006 输出状态。

## 按需

- WF-003 学习阶段；
- WF-008 知识过时；
- WF-009 项目完成；
- WF-010 迁移批次。

## 阶段性

- 每个 Design D、内容 Phase 或迁移批次结束时，使用工作流执行记录完成复盘；
- D10 将对十条工作流进行最终端到端演练。
