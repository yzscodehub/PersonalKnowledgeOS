# MOC、学习路线、索引、仪表盘与 Manifest 规范

## 目标

导航对象分别承担“理解、学习、查找、行动和规划”，避免同一份清单被人工维护多次。

## 统一地图模型

```yaml
type: map
map_kind: moc
```

`map_kind` 允许：

| 值 | 职责 | 主要回答 |
|---|---|---|
| `moc` | 人工策展的主题知识网络 | 这个主题包含什么，关系是什么？ |
| `learning-route` | 目标驱动的有序学习路径 | 为达到目标应按什么顺序学习？ |
| `index` | 尽量完整的查找入口 | 某类内容在哪里？ |
| `dashboard` | 动态状态和行动入口 | 现在需要关注和处理什么？ |

## MOC

MOC 负责：

- 解释主题边界；
- 选择核心文章；
- 展示前置、分支、应用、对比和实验；
- 为同一批文章提供稳定视角；
- 说明尚未建设的主题，但不制造失效链接；
- 指向相关学习路线、索引和来源入口。

MOC 不负责：

- 收录每一篇文章；
- 管理动态状态；
- 维护完整学习进度；
- 保存正式定义和推导；
- 为尚未建设主题创建空 Markdown。

### MOC 准入

出现以下情况时建立 MOC：

- 一个主题已有 5～15 篇以上相关正式文章；
- 文章关系不能由单一目录顺序表达；
- 主题存在多个分支、应用或验证路径；
- 需要长期维护主题边界和核心入口。

文章很少时优先在领域总览中组织，不提前创建大量 MOC。

## 学习路线

学习路线必须声明：

- 目标和受众；
- 前置能力；
- 完成标准；
- 阶段顺序；
- 每阶段的知识、练习和实验；
- 检查点和退出条件；
- 可以跳过或替代的路径。

规则：

- 可以跨知识领域；
- 同一文章可以出现在多条路线；
- A/B/C 优先级只在具体路线中成立；
- 路线不改变文章主归属；
- 路线不复制 MOC 的完整主题说明；
- 路线不把计划主题实例化为空文件。

## 索引

索引负责快速查找：

- 术语；
- 公式；
- 算法；
- API；
- 实验；
- 故障；
- 来源；
- 输出。

规则：

- 条目简洁；
- 尽量覆盖已经存在的内容；
- 可以由脚本生成候选，人工确认；
- 不解释学习顺序；
- 不复制文章摘要和证据；
- 已废弃内容标记替代文章。

## 仪表盘

仪表盘面向当前行动和动态状态：

- 收件箱积压；
- 活跃、等待和暂停项目；
- 责任领域风险；
- 待验证、待更新和废弃知识；
- 正在阅读和长期未读来源；
- 草稿、待审核和已发布输出；
- 自动化警告和近期系统工作。

仪表盘优先使用 Properties 和查询生成，不人工维护与其他对象完全重复的清单。

仪表盘中的一条状态变化应回写对象自身，而不是只修改仪表盘。

## Manifest

Manifest 是建设计划和机器状态，不是所有文件的人工目录。

### 负责内容

- 计划中的稳定主题 ID；
- 唯一主归属；
- 目标文章类型；
- 建设状态；
- 前置依赖 ID；
- 目标文件路径；
- 当前路线或批次优先级；
- 来源和验证要求；
- 建设批次和负责人（需要时）。

### 不负责内容

- 所有来源、日记和输出的登记；
- 已经存在但不需要规划的临时文章；
- 语义关系的完整解释；
- 当前阅读进度和项目行动；
- 替代 MOC、索引或仪表盘。

### 状态

```text
planned
seed
outline
draft
stable
evergreen
```

- `planned`：只有 Manifest 条目，不存在文章文件；
- 从 `seed` 开始必须具有 `path`；
- 已实例化条目的 `status` 与文章 `maturity` 对齐；
- `deprecated` 和 `needs-update` 由文章 `lifecycle` 表达，不混入建设状态。

### 依赖

- 使用稳定 ID；
- 只登记真正阻断理解或实现的前置；
- 不把所有相关链接写成依赖；
- 依赖必须存在于 Manifest 或正式文章注册集中；
- 循环依赖需要人工审核，通常意味着文章边界不清。

### 路线优先级

```yaml
priority:
  graphics-foundation: A
  interview-review: A
  ai-foundation: C
```

A/B/C 只表示某条路线或建设批次的上下文优先级，不是文章的永久价值等级。

## 协作模型

```text
文件夹       = 稳定主归属
Properties   = 身份、类型和动态状态
正文链接     = 语义关系和证据
MOC          = 主题知识网络
学习路线     = 面向目标的顺序
索引         = 快速查找
仪表盘       = 当前行动和动态状态
Manifest     = 建设计划与机器状态
```

同一信息只维护一个主版本：

- 文章标题和状态在文章中；
- MOC 只维护策展关系；
- 路线只维护顺序和检查点；
- 索引只维护查找入口；
- 仪表盘通过查询读取状态；
- Manifest 只维护建设元数据。

## 查找和使用顺序

```text
不知道放哪里       → 信息归属规则
想理解主题结构     → MOC
想按目标学习       → 学习路线
知道名称想快速找   → 索引或搜索
想处理当前状态     → 仪表盘
想规划未来建设     → Manifest
想获得正式解释     → 知识文章
```

## 路径变化

移动或重命名文章时：

1. 保留稳定 `id`；
2. 更新 Manifest `path`；
3. 依赖 Obsidian 更新 WikiLink；
4. 旧标题有搜索价值时加入 `aliases`；
5. 检查 MOC、路线、索引和来源反向链接；
6. 运行校验；
7. 存在外部路径引用时建立替代页或发布重定向。

## 跨领域导航

- 基础主文章保持唯一主归属；
- 应用文章放在应用领域；
- 跨领域 MOC 放在 `99 跨领域知识地图`；
- 跨领域 MOC 只组织已存在文章；
- 路线可以跨领域；
- Manifest 中仍为每篇文章记录唯一主归属。

## 一致性检查

自动化逐步检查：

- `type: map` 是否具有合法 `map_kind`；
- `planned` 主题是否未提前创建路径；
- `seed` 及以上主题是否存在路径；
- Manifest ID 和文章 ID 是否一致；
- Manifest 状态和文章成熟度是否一致；
- ID 和路径是否唯一；
- 依赖 ID 是否存在；
- MOC、路线和索引是否存在失效或歧义链接；
- 废弃文章是否在导航中标明替代关系。
