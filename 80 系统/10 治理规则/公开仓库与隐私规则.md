# 公开仓库与隐私规则

## 当前运行模式

当前仓库保持公开，并采用 **public-safe（公开安全）模式**。

在该模式下，仓库可以保存：

- 可公开的数学、计算机科学、图形学、AI 和软件工程知识；
- 不含雇主机密、个人身份信息和敏感上下文的技术项目记录；
- 可公开的来源笔记、实验、脚本和技术输出；
- 知识库架构、治理规范、模板和自动化；
- 已确认拥有公开权利的图片、代码和附件。

## 禁止进入公开仓库的内容

以下内容在仓库转为私有之前不得提交：

- 医疗记录、检查报告、用药信息和健康隐私；
- 财务账户、账单、收入、税务和支付信息；
- 身份证件、地址、电话号码、私人邮箱等个人身份信息；
- 密码、Token、Cookie、API Key、SSH 私钥和恢复码；
- 雇主或客户的未公开代码、文档、截图、数据和商业信息；
- 未公开的求职、薪资谈判、合同、劳动争议和人事资料；
- 私人日记、家庭关系、个人对话和不希望长期公开的决定；
- 受版权保护的整本书、课程资源或无权再发布的附件；
- 任何仅因“以后可能改成私有”而暂时提交的敏感内容。

## 对行动目录的限制

仓库公开期间，以下目录只允许保存可公开内容：

```text
00 收件箱
10 项目
20 责任领域
50 输出
60 日记与回顾
_assets
```

这些目录存在是为了验证完整知识系统结构，不代表可以在公开模式下保存私人信息。

例如，`10 项目` 可以记录“完成 PBR 渲染器”，但不能记录雇主内部项目、客户数据或私人求职谈判；`20 责任领域` 只能维护可公开的能力标准和技术责任；`60 日记与回顾` 只能保存可公开的学习日志和技术复盘。

## 转为私有仓库的触发条件

出现以下任一需求时，应在写入内容 **之前** 将仓库改为私有：

- 开始维护健康、财务、家庭或私人日记；
- 需要保存真实工作过程、雇佣资料或未公开项目；
- 需要保存私人附件、合同、截图或聊天记录；
- 希望把该仓库真正作为包含个人生活管理的完整 Personal OS。

转为私有后，可继续沿用现有目录和链接结构，无需重构知识层。

## 误提交处理

仅把仓库从公开改为私有，不能撤回已经公开过的历史内容。

若敏感信息曾被提交：

1. 立即删除工作区中的敏感文件；
2. 对凭据、Token、密码和密钥立即轮换或吊销；
3. 使用 Git 历史重写工具从所有提交中移除内容；
4. 检查 Fork、缓存、Actions 日志和已发布附件；
5. 记录事故和修复范围；
6. 必要时将仓库改为私有。

## 本地私密草稿

公开仓库模式下，临时私密内容只能存放在 Git 忽略的位置，例如：

```text
_private/
*.private.md
*.secret.md
```

但 `_private` 不是长期私人知识库方案。需要长期维护私人内容时，应切换仓库可见性。

## 提交前检查

每次提交前至少确认：

- 是否包含个人身份、健康、财务或雇佣信息；
- 是否包含凭据、环境变量或访问地址；
- 是否包含无权公开的代码、截图、图书或附件；
- 文件名、图片 EXIF、日志和代码注释是否泄露敏感上下文；
- 来源笔记是否以个人重述为主，而不是大段复制原文。
