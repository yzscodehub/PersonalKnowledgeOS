# 知识对象类型与文章原型规则

## 目标

正式知识文章按“主要回答的问题”选择类型，而不是按来源、文件长度、平台或当前项目选择类型。

## 允许类型

| type | 主要问题 | 必要内容 |
|---|---|---|
| `concept` | 它是什么，与相邻概念如何区分？ | 定义、边界、应用或反例 |
| `theory` | 为什么成立，在什么假设下成立？ | 假设、结论、推导或证明 |
| `algorithm` | 如何计算，步骤和不变量是什么？ | 输入输出、步骤、正确性、复杂度 |
| `system` | 组件如何协作，状态和生命周期如何流动？ | 边界、组件、数据流、状态、失败路径 |
| `implementation` | 在明确环境中如何实现？ | 环境、结构、数据、生命周期、测试 |
| `api-reference` | 接口契约、约束和版本差异是什么？ | 规范、对象、生命周期、错误、官方来源 |
| `experiment` | 如何验证，结果是否可复现？ | 假设、环境、变量、步骤、原始结果、局限 |
| `troubleshooting` | 如何定位、修复并验证故障？ | 症状、环境、假设、根因、修复、验证 |
| `comparison` | 在明确标准下应如何选择？ | 上下文、候选、标准、证据、决策矩阵 |

`principle` 不再使用。概念规律归入 `concept`，形式规律归入 `theory`，系统治理原则归入系统设计或治理规则。

## 类型选择顺序

```text
是什么        → concept
为什么成立    → theory
如何计算      → algorithm
如何协作      → system
如何实现      → implementation
接口是什么    → api-reference
如何验证      → experiment
如何排障      → troubleshooting
如何选择      → comparison
```

一篇文章只有一个主类型。辅助章节不改变主类型。

## 原型最低要求

### Concept

达到 `draft` 时应具有：

- 清晰定义；
- 至少一个非例或相邻概念边界；
- 至少一个典型应用；
- 来源或其他验证证据。

### Theory

达到 `draft` 时应具有：

- 符号和假设；
- 明确结论；
- 可定位推导、证明或机制推演；
- 边界、反例或数值检查。

### Algorithm

达到 `draft` 时应具有：

- 输入、输出和前置条件；
- 步骤或伪代码；
- 不变量或正确性解释；
- 复杂度和失败条件。

### System

达到 `draft` 时应具有：

- 系统边界和非目标；
- 组件职责；
- 数据流、控制流或状态机；
- 生命周期、所有权和失败路径。

### Implementation

达到 `draft` 时应具有：

- 平台、版本、代码库或运行环境；
- 依赖的基础文章；
- 数据结构和执行流程；
- 资源生命周期、错误处理和测试方法。

### API Reference

达到 `draft` 时应具有：

- 官方规范或文档；
- 版本和平台；
- 接口语义、生命周期和约束；
- 最小使用流程；
- 错误、同步、线程或资源边界。

### Experiment

达到 `stable` 时必须：

- 环境和变量可追踪；
- 原始结果与分析分离；
- 具有可运行代码、数据或明确复现步骤；
- `verification` 包含 `experiment-reproduced`。

### Troubleshooting

达到 `stable` 时应具有：

- 可描述的环境和复现条件；
- 排查假设和证据；
- 根因或明确标记为经验性修复；
- 修复后的验证结果；
- 预防或监控方式。

### Comparison

达到 `draft` 时应具有：

- 明确决策上下文；
- 可比版本和控制条件；
- 评价标准；
- 证据化对比；
- 场景化建议，而不是无条件排名。

## 模板选择

- 通用入口：[[80 系统/20 模板/文章原型选择指南|文章原型选择指南]]；
- 类型专用模板优先于通用知识模板；
- 模板章节可以删除、重排和增补，不要求机械填满；
- Frontmatter 的 `type` 必须与文章实际主问题一致。

## 类型变更

文章在 `seed` 或 `outline` 阶段可以直接调整类型。达到 `draft` 后变更类型时：

1. 说明主问题为何变化；
2. 检查标题、结构和 ID 是否仍代表同一知识对象；
3. 若已变成另一个独立问题，应新建文章而不是只改 `type`；
4. 更新 Manifest、MOC、路线和模板引用；
5. 运行校验。
