# 端到端工作流与回流规则

## 目标

让信息在收件箱、项目、责任领域、知识、来源、输出、日记和档案之间流动时，始终保持唯一主归属、明确状态、可追踪证据和可回滚历史。

完整流程见 [[80 系统/13 D3 端到端工作流设计|D3 端到端工作流设计]]。

## 一、每次执行只选择一个主对象

工作流开始时必须明确当前主对象：

```text
捕捉      收件箱条目
阅读      来源笔记
学习      学习路线或学习项目
工程决策  项目主页／项目决策
故障      故障记录或 troubleshooting 文章
发布      输出主页
回顾      日记或周期回顾
知识更新  正式知识文章
项目归档  项目主页
迁移      迁移批次
```

主对象负责当前状态和下一步。其他对象只保存链接、证据或结果，不重复维护同一状态。

## 二、交接采用“创建目标＋回写链接＋清理临时对象”

对象从一个角色转入另一个角色时：

1. 在目标角色创建或更新正式对象；
2. 在原对象记录目标链接和处理结论；
3. 同步 Manifest、MOC、来源反向链接、项目输出或责任领域；
4. 临时对象无历史价值时删除；
5. 有过程价值时保留，但不得继续作为正式状态源；
6. 运行校验。

禁止通过复制全文完成交接。

## 三、稳定结论回流到唯一正式位置

| 产生位置 | 稳定内容 | 回流位置 |
|---|---|---|
| 收件箱 | 明确问题、行动、来源或输出意图 | 对应正式角色 |
| 来源 | 可复用解释、定义和证据 | 正式知识 |
| 学习路线 | 修正后的理解和实验结果 | 知识、实验、实现 |
| 项目 | 通用决策、实现模式和权衡 | 知识、比较、实现、实验 |
| 故障排查 | 根因、修复模式和监控信号 | troubleshooting、system、implementation |
| 输出 | 事实修正、读者问题和解释改进 | 正式知识、来源、新项目 |
| 日记／回顾 | 行动、风险、稳定理解 | 项目、责任领域、知识、来源、输出 |
| 迁移 | 去重后的主版本和旧链接 | 新结构、Manifest、legacy_ids |

回流完成后，原记录保留时间或项目上下文，但不成为长期结论的唯一副本。

## 四、状态变化必须发生在所属对象中

- 收件箱：`unprocessed / clarify / routed / discarded`；
- 项目：`planned / active / waiting / paused / completed / cancelled`；
- 责任领域：`active / watch / at-risk / paused / retired`；
- 来源：`unread / reading / processed / reference / abandoned`；
- 输出：`idea / draft / review / ready / published / retired / cancelled`；
- 正式知识：`maturity`、`verification`、`lifecycle`；
- 周期回顾：`open / completed`；
- 迁移批次：`planned / inventory / classified / transforming / validating / accepted / rolled-back / paused`。

不在另一个页面用文字模拟同一状态机。

## 五、异常不得被伪装成完成

- 项目未达到完成条件但停止：`cancelled`；
- 故障无法确认根因：`unresolved` 或明确经验性修复；
- 来源不支持声明：不得添加 `source-checked`；
- 实验不可复现：不得添加 `experiment-reproduced`；
- 文章证据不足：保持真实成熟度；
- 迁移未通过校验：`paused` 或 `rolled-back`；
- 输出未达到发布条件：保持 `draft/review` 或取消。

## 六、工作流应以最小充分证据停止

工作流不是无限研究。达到当前目标所需的最小充分证据后应结束本轮：

- 捕捉：已经确定主归属；
- 阅读：阅读问题已回答，结论有定位；
- 学习：达到能力完成标准；
- 项目决策：已有可执行方案和风险说明；
- 故障：修复已验证，或明确缓解／未解决状态；
- 输出：完成发布和反馈回流；
- 回顾：关键变化已写回正式对象；
- 过时知识：恢复有效或完成替代；
- 项目归档：知识、输出和后续事项有去向；
- 迁移：批次通过校验且可回滚。

## 七、复杂工作流使用执行记录

满足以下任一条件时，使用 [[80 系统/20 模板/工作流执行记录模板|工作流执行记录模板]]：

- 跨越三个以上信息角色；
- 持续超过一周；
- 存在高风险、隐私、版权或生产影响；
- 需要回滚；
- 需要在 D10 作为正式演练证据；
- 工作流失败后需要复盘。

简单捕捉、阅读或项目更新直接写在主对象中。

## 八、自动化只检查结构，不替代判断

自动化负责：

- 工作流清单完整性；
- 状态和必填字段；
- Manifest、链接、ID、来源反向链接和实验路径；
- 公开安全和附件；
- 失效、超期和待更新候选。

人工负责：

- 主归属；
- 来源是否支持声明；
- 根因与决策；
- 成熟度和完成标准；
- 是否公开、发布、归档或删除。

## 九、工作流变更规则

- 新增或删除核心工作流必须创建 ADR；
- 修改状态机或跨角色边界需要更新 D1、D2、D3 和模板；
- 仅调整执行细节可以直接更新规则并记录 CHANGELOG；
- D10 演练发现问题时，先修正规则和模板，再重新演练；
- 工作流数量应保持少而完整，避免为每个小动作创建新流程。

## 十、当前核心工作流

```text
WF-001 快速捕捉与正式归属
WF-002 来源阅读与知识提炼
WF-003 学习路线与实验验证
WF-004 项目问题与知识回流
WF-005 故障排查与修复验证
WF-006 知识输出与发布回流
WF-007 日记和周期回顾
WF-008 过时知识与替代
WF-009 项目完成与归档
WF-010 旧内容迁移与回滚
```
