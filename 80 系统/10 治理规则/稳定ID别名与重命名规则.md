# 稳定 ID、别名与重命名规则

## 目标

文章标题、路径和主归属会随着理解改进而变化，但稳定身份不应随文件移动反复变化。本规则区分：

```text
id          稳定身份
标题        当前最清晰的名称
文件路径    当前主归属
aliases     搜索和术语入口
legacy_ids  旧知识库映射
```

## ID 格式

正式知识使用：

```text
<DOMAIN>-<MODULE>-<NNN>
<DOMAIN>-<CATEGORY>-<MODULE>-<NNN>
```

示例：

```text
MATH-LA-001
GFX-PROJ-002
GFX-EXP-TRANSFORM-001
```

格式要求：

- 只使用大写英文字母、数字和连字符；
- 总段数 3～5；
- 最后一段为三位数字；
- 同一仓库中唯一；
- 不包含日期、成熟度、版本号和文件夹序号。

## 领域前缀

| 前缀 | 领域 |
|---|---|
| `MATH` | 数学 |
| `PHYS` | 物理与工程科学 |
| `CS` | 计算机科学 |
| `GFX` | 图形学与渲染 |
| `AI` | 人工智能与数据科学 |
| `SWE` | 软件工程 |
| `SYS` | 系统与平台 |
| `ENG` | 游戏引擎与实时应用 |
| `MEDIA` | 音视频与多媒体 |
| `ROB` | 嵌入式、机器人与智能驾驶 |
| `DESIGN` | 设计、摄影与内容创作 |
| `BIZ` | 产品、商业与职业发展 |
| `HUM` | 人文与社会科学 |
| `KB` | 知识库系统 |

模块前缀由领域蓝图或 Manifest 管理。已有模块前缀可以继续使用，不为了统一缩写反复修改已发布 ID。

## ID 分配时机

- `planned` 主题在 Manifest 中可以先获得 ID；
- 未进入 Manifest 的临时 `seed` 文章，在创建正式文件时分配 ID；
- 收件箱、日记和普通来源不使用知识 ID；
- 地图只有被 Manifest、发布系统或外部工具稳定引用时才按需分配 ID。

## ID 稳定性

以下变化不修改 ID：

- 标题改进；
- 文件名改进；
- 移动到更正确的模块或领域；
- 文章类型在同一知识对象范围内调整；
- 内容成熟度变化；
- 来源和验证证据变化。

只有以下情况允许变更：

- 两个对象误用了同一 ID；
- 一个 ID 被错误分配给完全不同的问题；
- 合并后决定保留另一个更稳定的主 ID；
- 导入旧库时发生冲突。

变更时必须记录迁移映射，并检查所有 Manifest、项目、输出和外部引用。

## `aliases`

使用列表：

```yaml
aliases:
  - Perspective Division
  - 透视除法
```

适用：

- 稳定中英文名称；
- 行业通用缩写；
- 重命名前仍可能被搜索的旧标题；
- 同义但不适合作为主标题的术语。

不适用：

- 当前一级标题；
- 拼写错误；
- 一次性口语表达；
- 上位分类；
- 标签或状态；
- 为提高搜索命中而堆积的大量关键词。

通常控制在 1～8 个，并去重。

## `legacy_ids`

旧知识库迁移使用列表：

```yaml
legacy_ids:
  - OLD-GFX-102
  - graphics/math/matrix-note
```

规则：

- 一个新主文章可以接收多个旧 ID；
- 同一个旧 ID 不能出现在多个新文章中；
- 旧 ID 不替代当前 `id`；
- 旧路径、旧数字 ID 和外部系统 ID 都可以记录；
- 迁移完成后仍长期保留，用于追踪和重定向。

`legacy_id` 单值字段视为旧写法，后续迁移统一转换为 `legacy_ids` 列表。

## 标题和文件名

- 一级标题表达当前最清晰的问题或对象；
- 文件名默认与一级标题一致；
- 文件名不强制包含 ID；
- 不使用“最终版”“新版”“详细介绍”“学习笔记”等状态词；
- 对比文章使用稳定候选名，不在标题中直接下结论；
- 应用文章在必要时加入上下文，如“傅里叶分析在纹理过滤中的应用”。

## 重命名流程

1. 确认知识对象本身未变化；
2. 修改文件名和一级标题；
3. 保留 `id`；
4. 依赖 Obsidian 自动更新 WikiLink；
5. 旧标题仍有搜索价值时加入 `aliases`；
6. 更新 Manifest `path`；
7. 检查 MOC、路线、索引和来源反向链接；
8. 运行校验；
9. 存在外部 URL 或非 Obsidian 路径引用时，保留替代页或发布重定向。

## 移动流程

移动文章只表示主归属变化：

- 保留 ID；
- 更新 `domain` 和必要模块说明；
- 更新 Manifest 路径；
- 检查跨领域 MOC 和应用文章；
- 不在旧目录保留重复正文；
- 若外部路径必须保留，旧路径只保留重定向或替代说明。

## 合并时的 ID

- 选择主归属正确、引用最稳定、内容最完整的 ID；
- 其他旧 ID 可以加入 `legacy_ids`，或由替代页保留；
- 不能把两个仍然独立的问题强行合并到一个 ID；
- 合并后 Manifest 和所有依赖只指向主 ID。

## 自动化要求

逐步检查：

- ID 格式；
- ID 唯一性；
- `aliases` 为列表且不重复；
- `legacy_ids` 为列表且跨文章唯一；
- Manifest ID 与文章 ID 一致；
- 重命名后路径和链接有效。
