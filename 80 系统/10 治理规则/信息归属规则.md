# 信息归属规则

## 核心原则

每条信息只有一个稳定主归属。状态、关系和使用上下文通过 Properties、正文链接、MOC 和 Manifest 表达，不通过复制或频繁移动表达。

## 一分钟决策树

依次询问：

1. **当前是否无法判断用途或归属？**
   - 是：进入 `00 收件箱`，一周内再次处理。
2. **是否有明确成果、完成条件，并需要多步推进？**
   - 是：进入 `10 项目`。
3. **是否是需要长期维持的责任、标准、风险或状态？**
   - 是：进入 `20 责任领域`。
4. **是否是可脱离当前日期、项目或来源复用的解释、模型、方法或结论？**
   - 是：进入 `30 知识`。
5. **主要价值是否是出处、版本、章节、数据、源码或证据入口？**
   - 是：进入 `40 来源`。
6. **是否面向明确受众，并具有文章、视频、课程、演示或文档等交付形式？**
   - 是：进入 `50 输出`。
7. **主要价值是否是记录某天、某周、某月或某阶段发生的过程？**
   - 是：进入 `60 日记与回顾`。
8. **是否是知识库自身的规则、模板、设计、ADR、Manifest 或自动化？**
   - 是：进入 `80 系统`。
9. **是否已经退出日常维护，但仍有历史、证据或恢复价值？**
   - 是：进入 `90 档案`。
10. **是否没有长期价值？**
    - 是：删除。

## 目的补全法

仍然犹豫时，补全：

> 我保留它，是为了 ______。

| 目的 | 主归属 |
|---|---|
| 完成一个明确结果 | 项目 |
| 长期维持一个标准 | 责任领域 |
| 以后理解和复用 | 知识 |
| 追踪证据和出处 | 来源 |
| 交付给读者、观众或项目成员 | 输出 |
| 保留时间过程和上下文 | 日记与回顾 |
| 管理知识库自身 | 系统 |
| 保留历史和恢复能力 | 档案 |
| 暂时无法补全 | 收件箱 |

## 常见边界

### 项目与责任领域

- “三个月完成一个 Vulkan Demo”是项目；
- “长期保持图形学职业竞争力”是责任领域；
- 责任领域风险需要多步修复时，触发一个项目；
- 项目完成后，更新责任领域标准和状态。

### 项目与输出

- 项目保存计划、决策、过程和复盘；
- 输出保存文章、脚本、演示、教程等交付物；
- 项目归档后，仍有长期价值的输出继续保留。

### 来源与知识

- 按一本书章节组织的阅读笔记是来源；
- 从多个来源重组出的稳定解释是知识；
- 来源笔记反向链接已提炼知识，不复制正式正文。

### 日记与正式内容

- 当天发生的过程留在日记；
- 可复用结论提炼到知识；
- 行动更新到项目；
- 长期风险更新到责任领域；
- 证据入口更新到来源。

### 知识与档案

- 过时知识通常保留原路径，使用 `lifecycle: deprecated` 和 `superseded_by`；
- 只有退出知识网络且仍需保存历史的特殊内容才进入档案。

## 稳定归属与动态状态

- 文件夹表达稳定主归属；
- `status`、`maturity`、`verification`、`lifecycle` 表达动态状态；
- 正文链接表达语义关系；
- MOC 和学习路线表达视角与顺序；
- Manifest 表达建设计划；
- 不因进行中、等待、已阅读、待验证等状态变化移动文件。

## 公开安全

当前仓库公开。任何角色都不得提交：

- 凭据和账户信息；
- 私人健康、财务、合同和聊天内容；
- 雇主机密、未公开代码和数据；
- 无权公开的附件与来源文件。
