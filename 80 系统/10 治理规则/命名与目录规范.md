# 命名与目录规范

## 目录职责

- 顶层目录表达信息角色；
- `20 责任领域` 表达长期责任、状态和维护标准；
- `30 知识` 下的一级目录表达知识领域；
- 模块目录只在已有一定内容规模时创建；
- 详细学习顺序优先放在 MOC，不把所有层级实体化为文件夹。

## 术语

```text
Area   = 责任领域
Domain = 知识领域
Module = 知识模块
Topic  = 知识主题
```

不要使用“领域”单独指代 Area。数学领域、图形学领域等仍表示知识 Domain。

## 文件命名

| 类型 | 命名方式 | 示例 |
|---|---|---|
| 项目 | 动词＋明确成果 | 完成 PBR 渲染器 |
| 责任领域 | 名词或责任范围 | 职业与技术能力 |
| 基础理论 | 稳定概念名 | 矩阵作为线性映射 |
| 应用文章 | 概念＋应用场景 | 傅里叶分析在纹理过滤中的应用 |
| 对比文章 | A 与 B | Forward 与 Deferred Rendering |
| 实验 | 目标＋实验 | Reversed-Z 深度精度对比实验 |
| 故障案例 | 症状或问题 | Seek 后音视频不同步 |
| 来源笔记 | 作者－标题 | Steven J. Gortler - Foundations of 3D Computer Graphics |
| 日记 | 日期 | 2026-08-04 |

## 编号规则

- 顶层目录使用十位编号表达稳定顺序；
- 知识领域使用两位编号；
- 模块目录可以使用编号，但文章文件名不强制编号；
- 文章稳定标识由 Frontmatter `id` 和 Manifest 管理，不依赖文件名编号。

## 避免使用

```text
最终版
最新版
新版
详细介绍
学习笔记
总结
副本
```

内容版本由 Git 和 `updated` 管理。

## 目录深度

默认目标：从仓库根目录到文章不超过五层。超过时应优先考虑 MOC、属性或更合理的模块边界。

## 附件命名

附件统一放入 `_assets`，建议使用：

```text
<article-id>-<purpose>-<sequence>.<ext>
```

例如：

```text
GFX-PROJ-002-frustum-01.svg
GFX-DEPTH-001-precision-chart-01.png
```
