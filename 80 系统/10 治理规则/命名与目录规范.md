# 命名与目录规范

## 目录职责

- 顶层目录表达信息角色；
- `20 责任领域` 表达长期责任、状态和维护标准；
- `30 知识` 下的一级目录表达知识领域；
- 模块目录只在已有足够真实内容时创建；
- 详细学习顺序放在学习路线，不把所有层级实体化为文件夹；
- 跨领域关系通过应用文章和 MOC 表达；
- 状态、平台和版本不进入目录名。

## 术语

```text
Area   = 责任领域
Domain = 知识领域
Module = 知识模块
Topic  = 知识主题
```

不要使用“领域”单独指代 Area。数学领域、图形学领域等仍表示知识 Domain。

## 文件命名

| 类型 | 命名方式 | 示例 |
|---|---|---|
| 项目 | 动词＋明确成果 | 完成 PBR 渲染器 |
| 责任领域 | 名词或责任范围 | 职业与技术能力 |
| Concept | 稳定概念名 | 齐次坐标 |
| Theory | 理论对象或结论 | 矩阵作为线性映射 |
| Algorithm | 算法或任务名 | SAH BVH 构建 |
| System | 系统或架构名 | RenderGraph 资源管理模型 |
| Implementation | 基础概念＋实现上下文 | Metal 中的 CVMetalTextureCache 管理 |
| API | 官方对象或接口名 | vkCmdPipelineBarrier2 |
| Experiment | 验证目标＋实验 | Reversed-Z 深度精度实验 |
| Troubleshooting | 症状或问题 | Seek 后音视频不同步 |
| Comparison | A 与 B | Forward 与 Deferred Rendering |
| 应用文章 | 概念＋应用场景 | 傅里叶分析在纹理过滤中的应用 |
| 来源笔记 | 作者－标题 | Steven J. Gortler - Foundations of 3D Computer Graphics |
| 日记 | 日期 | 2026-08-04 |

## 标题规则

- 标题表达当前最清晰的对象或核心问题；
- 一级标题默认与文件名一致；
- 不使用结论性夸张词和临时状态词；
- 对比文章标题不直接写“谁更好”；
- 应用文章加入必要上下文，防止与基础主文章混淆；
- API 文章优先保留官方接口名，中文解释放在正文或别名；
- 故障文章以可检索症状命名，而不是“问题记录”。

## 稳定 ID

文章稳定身份由 Frontmatter `id` 管理，不依赖文件名和目录编号。

格式：

```text
<DOMAIN>-<MODULE>-<NNN>
<DOMAIN>-<CATEGORY>-<MODULE>-<NNN>
```

示例：

```text
MATH-LA-001
GFX-PROJ-002
GFX-EXP-TRANSFORM-001
```

规则：

- 标题、文件名和路径变化时保留 ID；
- 文件名不强制添加 ID 前缀；
- 不把版本、日期、成熟度和优先级写入 ID；
- 详细规则见 [[80 系统/10 治理规则/稳定ID别名与重命名规则|稳定 ID、别名与重命名规则]]。

## 别名

别名使用 `aliases` YAML 列表，只记录：

- 稳定中英文名称；
- 行业通用缩写；
- 有搜索价值的旧标题；
- 常用同义术语。

别名不用于关键词堆积，不重复当前标题。

## 编号规则

- 顶层目录使用十位编号表达语义顺序；
- 知识领域使用两位编号；
- 模块目录可使用编号，但文章文件名不强制编号；
- 导航顺序不通过修改目录编号表达；
- Manifest 和路线负责建设与学习顺序。

## 顶层编号语义

```text
00        收件与捕捉
10～60    核心信息角色
70        保留扩展位，不创建实体目录
80        系统治理
90        档案
```

- 不为了填补编号创建新顶层目录；
- 新学科进入 `30 知识`；
- `experiments`、`scripts`、`.github` 是工程支持目录；
- 启用 `70` 或重编号必须创建 ADR；
- `80 系统` 和 `90 档案` 长期保持固定语义。

## 避免使用

```text
最终版
最新版
新版
详细介绍
学习笔记
总结
副本
未完成
待更新
已验证
```

版本、成熟度和生命周期由 Git 与 Properties 管理。

## 目录深度

默认从仓库根目录到文章不超过五层。超过时优先检查：

- 模块是否过度细分；
- 是否可由 MOC 表达；
- 是否只是状态、平台或版本目录；
- 是否应该建立应用文章而不是继续嵌套；
- 内容规模是否真的支持独立目录。

## 重命名和移动

1. 保留稳定 ID；
2. 修改文件名和一级标题；
3. 依赖 Obsidian 更新 WikiLink；
4. 旧标题有价值时加入 `aliases`；
5. 更新 Manifest 路径；
6. 检查 MOC、路线、索引和来源反向链接；
7. 运行校验；
8. 存在外部路径引用时保留重定向或替代页。

## 附件命名

附件统一放入 `_assets`：

```text
<article-id>-<purpose>-<sequence>.<ext>
```

例如：

```text
GFX-PROJ-002-frustum-01.svg
GFX-DEPTH-001-precision-chart-01.png
```
