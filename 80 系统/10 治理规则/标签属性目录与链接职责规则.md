# 标签、属性、目录与链接职责规则

## 目标

避免同一信息同时写入目录、标签、Properties 和正文列表，导致重复维护和冲突。

## 总体分工

```text
目录          稳定主归属
Properties    身份、类型、状态和机器查询字段
正文链接      人需要理解的语义关系
MOC／路线     主题结构和学习顺序
索引          查找入口
仪表盘        动态状态
Manifest      建设计划
标签          少量临时跨切面检索
```

## 目录

目录只回答：

> 这篇内容的稳定主归属是什么？

目录适合表达：

- 顶层信息角色；
- 知识领域；
- 内容规模足够后的稳定模块；
- 档案中的原角色分区。

目录不表达：

- 进行中、等待、已完成；
- 待验证、待更新；
- 学习顺序；
- 平台、API 和版本；
- 所有知识关系；
- 当前项目优先级。

## Properties

Properties 用于机器查询、校验和自动化。

正式知识常用：

```text
id
type
domain
maturity
verification
lifecycle
aliases
platforms
apis
versions
version_sensitive
legacy_ids
superseded_by
```

规则：

- 保持最小字段；
- 只有实际需要查询或校验时增加字段；
- 列表字段必须使用 YAML 列表；
- 不维护与正文重复的巨大 `related`、`links` 或 `topics` 列表；
- 不通过 Properties 重建完整知识图谱。

## 正文链接

WikiLink 用于表达需要解释的语义关系：

- 前置知识；
- 上层应用；
- 对比和边界；
- 实现和实验；
- 来源和证据；
- 替代和演化；
- 项目、输出和责任领域中的使用关系。

推荐写法：

```markdown
非均匀缩放下不能直接用普通方向矩阵变换法线，原因见
[[矩阵作为线性映射]]，实际渲染处理见
[[Object 到 World 变换]]。
```

比只维护无上下文的“相关链接”列表更有价值。

## 标签

### 默认策略

本知识库不要求任何全局标签，也不建立完整标签分类树。

### 标签不能替代

- 知识领域目录；
- `type`；
- `maturity`、`status` 和 `lifecycle`；
- `platforms`、`apis` 和 `versions`；
- MOC、路线和索引；
- 来源与验证字段。

因此不建议：

```text
#graphics
#draft
#stable
#vulkan
#api
#book
```

这些信息已有更稳定的表达方式。

### 标签允许用途

标签只用于：

- 临时跨领域检索；
- 尚未值得建立正式字段的实验性分类；
- 短期人工审核批次；
- D8 迁移中的临时候选标记。

示例：

```text
#review-batch/source-cleanup
#migration-candidate/duplicate
```

标签应有明确清理日期或工作包。一个标签长期出现在 10 篇以上笔记，或被自动化依赖时，应升级为 Property、索引、MOC 或 Manifest 字段。

## MOC 和路线

- MOC 管理主题结构；
- 学习路线管理目标驱动的顺序；
- 不把 MOC 层级复制到目录和标签；
- 同一篇文章可以出现在多个 MOC 和路线中；
- 文章主归属不因出现在哪个 MOC 中而变化。

## 索引和仪表盘

- 索引用于查找，允许自动生成候选；
- 仪表盘用于动态状态，优先使用查询；
- 不手工同步一份与 Properties 完全重复的仪表盘清单；
- 索引和仪表盘都不是正式知识的唯一入口。

## Manifest

Manifest 只管理需要规划和自动化的建设对象：

- 尚未实例化的主题；
- 核心建设批次；
- 依赖、优先级、路径和状态；
- 目标来源和验证要求。

普通临时文章、日记、来源、输出和所有已存在笔记不必全部登记。

## 冲突处理

出现冲突时按以下优先级处理：

1. 主归属以正式设计和文章 `domain` 为准；
2. 身份以 `id` 为准；
3. 动态状态以 Properties 为准；
4. 语义解释以正文为准；
5. 建设计划以 Manifest 为准；
6. MOC、索引和仪表盘修正为对应视图；
7. 标签不得覆盖以上任何正式信息。

## 新字段或新标签准入

增加前回答：

- 是否已经可以由目录、正文链接或现有字段表达？
- 是否至少有三个真实使用场景？
- 是否需要查询或自动化？
- 谁负责维护？
- 何时删除或升级？

无法回答时不新增。
