# ADR-0014：完整设计后合并 Bootstrap 分支

## 背景

Gate A 和 Phase 1 试点已经通过，证明当前架构可以承载来源、数学、图形学、实验、MOC、学习路线和 Manifest。但 Personal Knowledge Base v3 的详细设计尚未覆盖所有信息角色、工作流、知识领域蓝图、Obsidian 体验、自动化、迁移、备份、发布和长期维护。

用户决定暂不合并 PR #1，继续在 `design/knowledge-base-v3` 分支完成整套设计。

## 决策

PR #1 和 `design/knowledge-base-v3` 分支保持 Draft 和未合并状态，直到 [[80 系统/09 完整设计收敛计划|完整设计收敛计划]] 全部通过。

“完整设计”指系统设计和可运行原型完整，不要求提前完成所有领域正文或旧知识库迁移。

## 合并前必须完成

1. 所有顶层信息角色的职责、状态、工作流和归档规则；
2. 知识文章类型、地图体系、Manifest、索引和来源证据的详细模型；
3. 捕捉、阅读、学习、项目、实验、输出、回顾、归档和迁移工作流；
4. 13 个知识领域的边界、一级模块蓝图和跨领域关系；
5. Obsidian 首页、仪表盘、模板、Bases／查询和核心配置设计；
6. 校验、日期、隐私、附件、Manifest、链接和一致性自动化设计；
7. Git 分支、PR、版本、发布、备份、恢复和灾难处理方案；
8. 旧知识库迁移、回滚和验收设计；
9. 长期维护节奏、过时内容处理和质量门禁；
10. 至少一条端到端工作流演练和完整设计复盘。

## 分支范围

允许在本分支继续：

- 总体设计、治理规则、ADR、模板、Manifest 和自动化；
- 为验证设计所需的最小示例和试点修复；
- 所有知识领域的蓝图、MOC 规划和迁移映射；
- Obsidian 与 Git 的使用和维护设计。

不允许在本分支扩大为内容生产：

- 不建设 Phase 2 光栅化正文；
- 不进入纹理、PBR、API 和 UE5 大规模文章建设；
- 不进行旧知识库全量迁移；
- 不创建大量空目录和空文章。

## 合并方式

完整设计验收后：

1. 清理全部临时迁移脚本和一次性工作流；
2. 运行全部 CI 和端到端设计检查；
3. 更新总体设计、路线图、README、CHANGELOG 和 PR 描述；
4. 将 PR #1 标记为 Ready；
5. 进行最终人工评审；
6. 使用 Squash Merge 合并为 `v0.2.0-complete-design-baseline`。

## 影响

- ADR-0013 被本决策取代；
- Phase 1 继续保持 `accepted`，但不触发合并；
- Phase 2 内容推迟到完整设计合并后的独立分支；
- 当前主要工作切换为“详细设计收敛”，而不是“最终合并检查”。
