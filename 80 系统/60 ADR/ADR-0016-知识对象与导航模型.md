# ADR-0016：冻结知识对象与导航模型

## 背景

知识库已经确定顶层信息角色，但正式知识仍可能因为文章类型、拆分粒度、命名、ID、标签和导航方式不明确而产生重复。尤其是同一主题可能同时出现在书籍笔记、项目记录、平台实现、学习路线和多个领域中。

## 决策

采用 [[80 系统/12 D2 知识对象与导航模型|D2 知识对象与导航模型]] 作为正式知识对象和导航系统的运行基线。

## 正式知识类型

只使用九种正式类型：

```text
concept
theory
algorithm
system
implementation
api-reference
experiment
troubleshooting
comparison
```

`principle` 不再作为独立类型。现有或未来“原则”根据内容归入概念、理论或系统治理文档。

## 唯一主解释

- 同一抽象层的稳定问题只有一个完整主解释；
- 通用理论放最基础的知识领域；
- 平台、引擎和业务领域建立应用文章；
- 来源不同、项目不同和学习路线不同不构成复制理由；
- 已有稳定引用的重复文章通过 `deprecated` 和 `superseded_by` 保留替代关系。

## 稳定身份

- 正式知识使用稳定 `id`；
- 标题、文件名、路径和主归属变化时原则上保留 ID；
- 别名使用 YAML 列表；
- 旧库映射使用 `legacy_ids` 列表；
- 重命名后依赖 Obsidian 修链，并更新 Manifest 路径。

## 导航职责

```text
文件夹       稳定主归属
Properties   类型、身份和动态状态
正文链接     语义关系和证据
MOC          主题知识网络
学习路线     目标驱动的学习顺序
索引         快速查找
仪表盘       动态状态和行动入口
Manifest     建设计划与机器状态
标签         少量临时跨切面检索，不承担分类体系
```

## 状态模型

- `maturity` 管理建设程度；
- `verification` 管理可累积证据；
- `lifecycle` 管理有效性和维护状态；
- 三者相互独立；
- `planned` 只存在于 Manifest，实例化后从 `seed` 开始。

## 自动化

校验脚本应检查：

- 正式知识类型是否合法；
- ID 格式和唯一性；
- `aliases`、`legacy_ids` 和 `superseded_by` 是否为列表；
- `deprecated` 文章是否给出替代关系或明确历史保留说明；
- `map` 是否具有合法 `map_kind`；
- Manifest 与实体文件是否一致。

## 影响

- Frontmatter 类型词表移除 `principle`；
- 新增文章类型选择指南和九种文章原型；
- 补充拆分、合并、替代、重命名和跨领域规则；
- D2 标记为完成；
- D3 工作流必须使用本 ADR 定义的对象和状态转换。
