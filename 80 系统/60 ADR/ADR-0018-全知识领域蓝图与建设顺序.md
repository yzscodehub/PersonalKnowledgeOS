# ADR-0018：全知识领域蓝图与建设顺序

## 背景

个人知识库不只服务图形学，还需要长期容纳数学、计算机科学、AI、软件工程、系统平台、游戏引擎、音视频、机器人、设计、产品和人文社科。若只在需要时临时增加目录，会产生以下问题：

- 相邻领域边界反复变化；
- 同一主题在多个目录重复建设；
- 旧库迁移时没有稳定目标；
- 为追求“完整”而提前创建大量空目录；
- 项目优先级与长期知识结构混为一体。

## 决策

为 `01`～`13` 知识领域及 `99 跨领域知识地图`分别建立正式领域蓝图。

每个蓝图冻结：

- 领域目标；
- 主归属边界；
- 稳定一级模块和模块代码；
- 核心基础、应用、来源和实践方式；
- 核心 MOC 候选；
- 跨领域关系；
- 首批建设建议；
- 非目标。

## 延迟实例化

蓝图中的模块、MOC 和主题默认只是逻辑规划。只有真实内容规模、近期项目或批准迁移批次需要时，才创建实体目录和笔记。

禁止通过批量创建空目录、空 MOC 和空文章表示蓝图已经实施。

## 建设顺序

领域编号不代表建设顺序。当前个人目标采用三波建设：

```text
Wave A  数学、计算机科学、图形学、软件工程、系统平台、
        游戏引擎、音视频、嵌入式／机器人／智能驾驶

Wave B  人工智能、设计与内容创作、产品与职业发展

Wave C  物理与工程科学、人文与社会科学
```

具体文章优先级仍由项目、学习路线和 Manifest 上下文决定。

## 跨领域原则

- 每篇正式文章只有一个主归属；
- 基础理论放最基础领域；
- 平台、引擎和业务上下文建立应用文章；
- 跨领域 MOC 连接现有文章，不复制正文；
- 不因真实问题横跨多个领域而创建新的含糊顶层目录。

## 影响

- D4 蓝图保存在 `80 系统/50 领域蓝图/`；
- 机器清单保存在 `80 系统/30 Manifest/知识领域蓝图清单.yaml`；
- 模块代码成为 Manifest、迁移映射和未来 ID 规划依据；
- D4 自动校验加入 CI；
- 旧库迁移和新领域建设必须引用蓝图；
- 领域或稳定模块的重大变更需要新 ADR。
