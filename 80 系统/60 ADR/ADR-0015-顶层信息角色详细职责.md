# ADR-0015：冻结顶层信息角色详细职责

## 背景

顶层目录已经按信息角色划分，但只有名称和简要定义不足以支撑日常使用。缺少进入条件、状态模型、离开条件、回顾频率和归档规则时，同一内容仍可能在项目、责任领域、知识、来源、输出和日记之间反复移动。

## 决策

采用 [[80 系统/11 D1 顶层信息角色详细设计|D1 顶层信息角色详细设计]] 作为顶层角色的正式运行规范。

核心边界：

```text
00 收件箱      临时捕捉与分流
10 项目        有成果和完成条件的多步工作
20 责任领域    无结束日期但需要维持标准的责任
30 知识        可脱离当前上下文复用的解释
40 来源        出处、版本、章节和证据入口
50 输出        面向受众的交付物
60 日记与回顾  时间过程和周期复盘
80 系统        知识库自身的规则和运行机制
90 档案        退出日常视图但需要保留和恢复的历史
```

## 运行原则

- 每个笔记只有一个稳定主归属；
- 动态状态使用 Properties，不建立状态目录；
- 收件箱普通内容一周内处理；
- 活跃项目必须有下一步行动；
- 责任领域通过标准、健康度和风险维护；
- 正式知识通常在原路径废弃和替代，不默认移动到档案；
- 来源、项目、输出和日记都应把稳定结论回流到正式知识；
- 档案原则上只读，恢复时回到原角色目录；
- 当前公开仓库的所有角色都遵守 public-safe 规则。

## 模板

新增并采用：

- 收件箱条目模板；
- 责任领域主页模板；
- 输出主页模板；
- 周回顾模板；
- 月度回顾模板；
- 档案索引模板。

项目、知识、来源和每日笔记继续使用现有模板。

## 影响

- 顶层 README 改为可执行的角色说明；
- 信息归属规则升级为一分钟决策树；
- D1 标记为完成；
- 下一阶段进入 D2 知识对象与导航模型；
- 后续 D3 工作流必须服从本 ADR 的主归属和状态边界。
