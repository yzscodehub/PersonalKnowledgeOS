# ADR-0004：公开仓库采用公开安全模式

## 背景

当前 Personal-Knowledge-Base 仓库是公开仓库，而总体架构包含收件箱、项目、责任领域、输出、日记和附件等可能承载私人信息的目录。

当前阶段主要建设可公开的技术知识、实验和知识库治理规范，暂时不计划保存健康、财务、私人日记、真实雇佣资料或其他敏感内容。

## 决策

当前仓库继续保持公开，并采用 **public-safe（公开安全）模式**。

在公开模式下：

- 只保存可公开的知识、来源笔记、实验、技术项目和输出；
- 行动目录可以保留，但只能写入可公开内容；
- 私人、医疗、财务、身份、雇佣机密和凭据不得提交；
- 本地临时私密内容放入 Git 忽略路径；
- 需要长期保存任何私人内容时，必须在写入前将仓库改为私有。

## 不采用的方案

### 当前立即改为私有

当前没有保存私人内容的需求，暂不增加不必要的可见性限制。

### 立即拆分私有 Personal OS 与公开 Knowledge Core

当前仓库规模较小，双仓库会提前引入跨仓库链接、同步、发布和维护成本。待未来同时出现“长期私人管理”和“持续公开发布”需求时再重新评估。

### 公开仓库中混合保存私人内容

不采用。依赖人工记忆避免泄露不可接受，并且 Git 历史可能长期保留误提交内容。

## 影响

### 正面影响

- 现有公开技术知识可以继续直接分享；
- 不需要现在拆分仓库或修改链接结构；
- 未来改为私有时可以继续沿用现有顶层架构；
- 明确了公开仓库的使用红线。

### 代价与约束

- `00 收件箱`、`10 项目`、`20 领域`、`60 日记与回顾` 等目录在公开期间用途受限；
- 提交前必须进行隐私和版权检查；
- 不能把“未来会改为私有”作为当前提交敏感内容的理由。

## 转为私有的触发条件

出现以下任一需求时重新执行仓库可见性决策：

- 开始记录健康、财务、家庭或私人日记；
- 保存真实工作项目、合同、人事或求职材料；
- 保存私人截图、聊天、账户资料或未公开输出；
- 将仓库升级为包含生活管理的完整 Personal OS。
