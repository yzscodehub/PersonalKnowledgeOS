# Git 工作流

## 分支策略

`main` 只保存已验收结构和稳定知识。设计、内容建设、迁移和自动化分别使用功能分支。

## Pull Request 内容

每个 PR 应说明：

- 本次解决的问题；
- 新增或修改的领域和文章；
- 使用的来源；
- 验证方式；
- 路径、ID 或链接迁移；
- 尚未解决的问题。

## Commit 粒度

一个 Commit 应表达一个可理解的变更，例如：

- 建立治理基础设施；
- 新增一个完整知识主题；
- 迁移一个旧模块；
- 修复一批链接；
- 增加一项自动校验。

## 合并前检查

```bash
python scripts/validate_kb.py
```

同时人工检查：

- 正文事实和推导；
- 来源是否匹配结论；
- MOC 和 Manifest 是否同步；
- 是否出现重复基础解释；
- 是否意外提交版权受限的原始资料或本地工作区状态。
