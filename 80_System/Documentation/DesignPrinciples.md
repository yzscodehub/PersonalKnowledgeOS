# PersonalKnowledgeOS Design Principles

## 1. Long-term Stability

The top-level structure should remain stable for years.

## 2. Separation of Concerns

- Knowledge stores understanding.
- Projects store execution.
- Sources store references.
- Outputs store created value.

## 3. Minimal Metadata

Only keep metadata that provides long-term value.

Current Knowledge Node metadata:

```yaml
---
title:
type:
domain:
status:
---
```

## 4. Link Over Duplication

Relationships are represented by links rather than repeated copies.

## 5. Knowledge Before Output

Build understanding first, then produce external results.
