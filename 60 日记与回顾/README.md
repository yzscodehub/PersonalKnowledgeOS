# 60 日记与回顾

日记与回顾记录**时间过程、上下文、变化和阶段性判断**，不承担长期知识正文职责。

## 建议结构

```text
10 每日笔记
20 每周回顾
30 月度回顾
40 季度与年度回顾
50 阶段复盘
```

只在真正开始使用对应周期时创建目录，不提前建立空结构。

## 每日笔记

可以记录：

- 当天重点；
- 项目进展和阻塞；
- 临时观察；
- 收件箱线索；
- 当天决策；
- 需要在周回顾处理的问题。

正式知识只保留链接或提炼线索，不在每日笔记中维护完整长期版本。

## 周回顾

每周至少完成：

- 清理收件箱；
- 检查活跃项目的下一步；
- 检查等待和暂停项目；
- 查看责任领域风险；
- 处理正在阅读来源；
- 提炼稳定知识；
- 更新输出状态；
- 归档已完成内容；
- 确定下一周重点。

周回顾是知识库的核心运行节奏。

## 月度回顾

月度回顾关注趋势和系统层调整：

- 责任领域健康度；
- 项目组合是否过载；
- 学习和输出是否产生结果；
- 知识、来源和输出积压；
- 需要停止、合并或归档的内容；
- 知识库维护成本是否可接受。

## 阶段复盘

阶段复盘用于：

- 项目阶段结束；
- 设计工作包结束；
- 迁移批次结束；
- 内容建设阶段结束；
- 重大故障或恢复演练结束。

阶段复盘不替代项目主页中的项目复盘。

## 稳定结论回流

回顾中发现的内容按角色写回：

- 行动和成果 → 项目；
- 长期标准和风险 → 责任领域；
- 稳定解释 → 知识；
- 证据入口 → 来源；
- 可交付内容 → 输出；
- 已结束历史 → 档案。

回顾笔记保留当时的判断和时间上下文，不作为正式结论的唯一副本。
