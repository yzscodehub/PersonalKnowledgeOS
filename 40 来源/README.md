# 40 来源

来源是知识的**证据入口和定位系统**，不是正式知识正文，也不是原始文件仓库。

## 来源类型

- 书籍；
- 论文；
- 官方文档与规范；
- 课程与视频；
- 文章与博客；
- 代码仓库与版本源码；
- 数据集与素材；
- 实验、调试捕获与生产记录；
- 访谈与对话。

## 状态模型

```text
unread → reading → processed
   ↘        ↘
 reference  abandoned
```

- `unread`：已登记，尚未系统处理；
- `reading`：正在阅读或提炼；
- `processed`：本轮目标已完成，关键内容已提炼；
- `reference`：不计划完整处理，只作长期查阅；
- `abandoned`：决定停止处理，并记录原因。

`processed`不代表来源永远完成；出现新问题时可以重新进入阅读状态。

## 来源笔记最低要求

进入`processed`前至少记录：

- 书目信息、版本或提交；
- 阅读目的；
- 可支持的声明类型；
- 关键章节、页码、URL或代码定位；
- 限制和适用范围；
- 已提炼知识的反向链接；
- 权利、许可和原始文件存储说明。

## 证据规则

来源价值取决于它能支持什么声明：

- 数学结论优先看证明、推导和权威教材；
- API语义优先看标准、规范和官方文档；
- 新算法优先看原始论文和独立复现；
- 具体实现行为看对应版本源码、实验和调试捕获；
- 性能结论依赖明确环境下的测量；
- 工程经验必须记录复现条件和适用边界。

不存在适用于所有问题的统一权威排序。

## 来源与正式知识

- 按来源结构组织的阅读记录留在这里；
- 从一个或多个来源重组出的稳定解释进入`30 知识`；
- 来源笔记反向链接已提炼文章；
- 正式知识不复制大段来源原文；
- `source-checked`只表示已用匹配声明类型的来源完成核对。

## 阅读队列与回顾

- `reading`来源：每周检查是否有明确下一步；
- 长期`unread`来源：每月决定阅读、降为`reference`或删除；
- 同时系统阅读的来源数量保持有限，避免阅读队列失控；
- 项目结束时检查项目来源是否需要提炼为长期参考。

## 归档

- 长期参考来源保留原路径并标记`reference`或`processed`；
- 低价值、重复或停止使用的来源可以移动到`90 档案/40 来源/`；
- 原始书籍、视频、模型和数据集不随来源笔记进入Git仓库。

## 原始文件与版权

来源笔记不等于原始文件归档。整本商业书籍和无权再分发的资料不入库；许可、定位和存储方式见 [[80 系统/10 治理规则/附件、版权与大文件规则|附件、版权与大文件规则]]。
