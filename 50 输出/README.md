# 50 输出

输出保存**面向明确受众、具有交付形式并值得长期维护的成果**。

项目负责生产过程，输出保存交付物。项目归档后，仍有价值的输出继续保留。

## 输出类型

- 技术文章；
- 教程与课程；
- 视频脚本；
- 演示文稿；
- 面试材料；
- 社交媒体内容；
- 可公开的项目文档。

## 状态模型

```text
idea → draft → review → ready → published
  ↘                         ↘
 cancelled                  retired
```

- `idea`：只有输出设想；
- `draft`：正在形成内容；
- `review`：等待事实、结构或表达审核；
- `ready`：可以交付或发布；
- `published`：已经发布或交付；
- `retired`：不再主动维护，但保留历史；
- `cancelled`：决定停止生产。

## 输出主页最低要求

- 目标受众和用途；
- 核心信息；
- 形式和平台；
- 关联项目；
- 使用的知识和来源；
- 当前状态和版本；
- 发布记录；
- 发布后反馈；
- 需要回流知识库的修正。

## 主版本与平台变体

同一输出主题可以维护一个规范主版本和多个平台变体：

```text
主题主页
├── 长文主版本
├── 短内容版本
├── 视频脚本
└── 演示文稿
```

平台变体可以调整标题、长度、语气和媒介结构，但共享核心事实和来源。

## 输出与项目

- “制作一套投影矩阵教程”是项目；
- 教程文章、视频脚本和演示文稿是输出；
- 项目中保存计划、过程和决策；
- 输出中保存可发布、可交付和可继续维护的版本。

## 发布后知识回流

发布或交付后检查：

- 是否发现事实错误；
- 是否出现更好的解释方式；
- 读者问题是否暴露知识缺口；
- 是否需要补来源或验证证据；
- 是否产生新项目或知识主题。

稳定修正必须回写正式知识，而不是只修改平台内容。

## 归档和保留

- 已发布且仍有价值的输出保留在这里；
- 已过时但需要历史链接的输出标记`retired`；
- 取消或失去长期价值的输出移动到`90 档案/50 输出/`；
- 发布平台不是唯一副本，仓库保存可维护主版本或必要元数据。
