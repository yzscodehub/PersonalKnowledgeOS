# 图形学坐标空间总览

## 问题与定位

三维渲染不是把顶点“一次变到屏幕”，而是在多个具有不同职责和约定的坐标空间之间转换。理解每个空间的几何意义、输入输出和不变量，是分析相机、投影、裁剪、深度、光照和 Shader 错误的基础。

本文使用列向量示意。具体引擎和 API 可能使用不同乘法、手性、深度范围和屏幕原点约定，必须以系统实际定义为准。

## 高层链路

$$
p_{world}=M_{model}p_{object}
$$

$$
p_{view}=M_{view}p_{world}
$$

$$
p_{clip}=M_{proj}p_{view}
$$

裁剪后执行透视除法：

$$
p_{ndc}=\left(
\frac{x_c}{w_c},
\frac{y_c}{w_c},
\frac{z_c}{w_c}
\right)
$$

最后通过视口变换映射到屏幕或 Render Target。

## 对象空间

对象空间也称 Model Space 或 Local Space。

- 网格顶点以模型自己的标架表达；
- 原点和轴通常由建模工具、导入规则或资产约定决定；
- 同一份网格可以通过不同 Model Transform 产生多个实例；
- 骨骼、切线空间和局部包围体通常也与对象局部标架相关。

对象空间解决“资产内部如何表达”的问题。

## 世界空间

Model Transform 把对象放入所有场景对象共享的世界空间：

$$
p_{world}=M_{model}p_{object}
$$

世界空间适合：

- 组织场景对象；
- 表达全局灯光、物理和空间查询；
- 比较不同对象的位置；
- 构建世界级加速结构。

大型世界可能在 CPU 使用双精度或分区坐标，在 GPU 使用相机相对坐标，避免大数减法导致的浮点精度损失。

## 观察空间

观察空间也称 View Space、Eye Space 或 Camera Space。View Transform 重新表达整个世界，使相机位于原点并对齐到约定的观察轴：

$$
p_{view}=M_{view}p_{world}
$$

若相机在世界中的标架矩阵为 $F_{camera}$，则通常：

$$
M_{view}=F_{camera}^{-1}
$$

观察空间把“任意位置和朝向的相机”转化为便于投影和裁剪的标准相机。

不同系统可能让相机看向 $-Z$ 或 $+Z$。这是一项约定，不是几何学必然规律。

## 齐次裁剪空间

投影矩阵输出四维齐次裁剪坐标：

$$
p_{clip}=(x_c,y_c,z_c,w_c)^T
$$

此时不能急于把它当作普通三维位置。$w_c$ 参与：

- 裁剪平面表达；
- 透视除法；
- 透视正确插值；
- 深度映射。

典型的横向裁剪条件是：

$$
-w_c\le x_c\le w_c
$$

$$
-w_c\le y_c\le w_c
$$

深度方向的条件取决于 API 和投影约定。

裁剪必须发生在透视除法之前。跨越相机平面或裁剪面的图元在 $w$ 接近零或变号时，先除法会产生无穷大、翻转和不连续。

## NDC

裁剪后对 $x_c,y_c,z_c$ 除以 $w_c$，进入 Normalized Device Coordinates。

NDC 是与具体分辨率无关的标准空间。通常 $x,y$ 落入 $[-1,1]$，但深度范围和 Y 方向依赖 API 及配置：

- OpenGL 传统深度范围常见为 $[-1,1]$；
- Direct3D 深度范围为 $[0,1]$；
- Vulkan 深度通常为 $[0,1]$，Y 和视口约定需要结合实际配置判断。

不能只说“Vulkan 或 OpenGL 的 Y 一定怎样”，还要检查负视口高度、投影矩阵修正和渲染目标原点等具体选择。

## 屏幕与视口空间

Viewport Transform 把 NDC 映射到 Render Target 的像素范围和深度范围。

需要明确：

- 视口左上角或左下角语义；
- 像素中心约定；
- Render Target 尺寸；
- Scissor 区域；
- 深度最小值和最大值；
- Front Face 绕序在 Y 翻转后是否改变。

屏幕像素坐标、纹理 UV 和图像文件原点不是同一个概念，混用会造成上下翻转和绕序错误。

## 不同几何量的变换

### 点

使用齐次 $w=1$，受平移、旋转和缩放影响。

### 方向和切向量

使用 $w=0$，不受平移影响。

### 法线

非均匀缩放下应使用线性部分的逆转置：

$$
n'\propto (A^{-1})^Tn
$$

然后重新归一化。原因是法线需要继续与变换后的切平面正交，而不是简单地和切向量执行相同变换。

## 组合顺序

在本文列向量约定下：

$$
p_{clip}=M_{proj}M_{view}M_{model}p_{object}
$$

最靠近向量的矩阵最先作用。若系统采用行向量，表达式和组合顺序会相反。不能把某个公式脱离乘法约定直接复制到另一套 API 或引擎。

Row-Major 与 Column-Major 描述内存布局，不足以判断使用行向量还是列向量。

## 调试坐标空间错误

### 明确命名输入输出空间

优先使用：

```text
ObjectToWorld
WorldToView
ViewToClip
WorldToClip
```

避免只有 `Transform` 或 `Matrix` 的含糊命名。

### 分阶段可视化

- 输出世界位置或观察空间位置为颜色；
- 绘制局部和世界坐标轴；
- 验证相机世界位置乘 View Matrix 后是否到原点；
- 检查裁剪前的 $w$；
- 输出 NDC 和深度；
- 用 Frame Capture 查看顶点阶段输出。

### 建立不变量测试

- 对象局部原点变换后应位于对象世界位置；
- 相机位置在观察空间应为原点；
- 近远平面应映射到约定深度端点；
- 点受平移影响，方向不受平移影响；
- 单位测试中矩阵和逆矩阵相乘应接近单位矩阵。

## 常见误区

- 把空间名称当成数据类型，却不记录具体约定；
- 在不同空间直接做点积、相加或距离计算；
- 混淆对象变换与坐标系换基；
- 把 Clip Space 和 NDC 当成同一空间；
- 在裁剪前执行透视除法；
- 依据内存布局判断矩阵乘法方向；
- 忽略 Y 翻转对绕序和剔除的影响；
- 用普通位置矩阵直接变换非均匀缩放下的法线。
