# 知识总览

`30 知识`保存**可以脱离当前日期、项目和单一来源长期复用的解释、模型、方法和结论**。

## 正式知识类型

```text
concept          概念和边界
theory           假设、结论和推导
algorithm        输入输出、步骤和复杂度
system           组件、数据流和生命周期
implementation   明确环境中的具体实现
api-reference    版本敏感的接口契约
experiment       可复现验证
troubleshooting  根因、修复和验证
comparison       明确标准下的场景化选择
```

## 正式知识准入

内容满足以下任一条件后，才进入正式知识：

- 可以脱离当前项目独立解释；
- 会被多个项目、输出或领域复用；
- 值得长期维护定义、推导、机制或边界；
- 已形成可验证的稳定问题；
- 需要成为其他文章的基础前置。

只有线索、摘录或阅读摘要时，先保留在收件箱、来源或项目中。

## 状态模型

知识使用三个独立维度：

```text
maturity      seed → outline → draft → stable → evergreen
verification  多证据列表
lifecycle     active / needs-update / deprecated / archived
```

- `maturity` 描述建设程度；
- `verification` 记录来源、推导、实验和生产证据；
- `lifecycle` 描述当前有效性和维护状态。

`planned` 只存在于 Manifest，文章实例化后从 `seed` 开始。

## 拆分、合并与唯一主解释

- 一篇文章解决一个稳定问题；
- 同一抽象层的基础概念只有一个完整主解释；
- 平台、引擎和业务上下文建立应用文章；
- 来源、项目和学习路线不同不构成复制理由；
- 两篇文章长期解释同一问题时，选择主版本并合并；
- 已有稳定引用的旧文章使用 `deprecated` 和 `superseded_by` 保留替代关系。

详细规则见 [[80 系统/10 治理规则/知识拆分合并与替代规则|知识拆分、合并与替代规则]]。

## 身份与重命名

- 正式知识使用稳定 `id`；
- 标题、文件名和路径变化时原则上保留 ID；
- 中英文术语和旧标题使用 `aliases`；
- 旧知识库映射使用 `legacy_ids`；
- 移动或重命名后更新 Manifest 路径并运行校验。

## 导航对象

```text
MOC          主题知识网络
学习路线     面向目标的顺序
索引         快速查找
仪表盘       动态状态和行动入口
Manifest     建设计划和机器状态
```

目录只表达主归属，Properties 表达身份和状态，正文链接表达语义关系。

## 废弃与历史

正式知识通常不移动到档案。过时内容保留原路径：

```yaml
lifecycle: deprecated
superseded_by:
  - "[[替代文章]]"
```

只有退出知识网络且仍需保留历史的特殊内容，才进入 `90 档案/30 知识历史/`。

## 回顾触发

知识不要求固定周期逐篇检查，优先在以下时机复核：

- 被项目或输出使用；
- 来源、规范或版本发生变化；
- 自动化标记 `needs-update`；
- 出现冲突证据；
- 准备升级成熟度；
- 对应 API、平台或产品更新。

## 组织规则

- 文件夹只表达稳定主归属；
- 学习顺序和跨领域关系由 MOC 与学习路线表达；
- 动态状态由 Properties 表达；
- 未建设文章只登记在 Manifest 中；
- 来源笔记放在 `40 来源`；
- 项目过程放在 `10 项目`；
- 面向受众的成品放在 `50 输出`；
- 标签不承担领域、类型和状态分类。
